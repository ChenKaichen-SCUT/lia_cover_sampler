# 第五轮：已有收益分解与同预算准备复用

**本次准备复用实现没有在相同总预算下增加可接受的覆盖收益，停止扩大实验。** 它减少了重复准备，在部分状态产生更多候选，但没有转化为预算内可交付的额外覆盖。60 ms 主比较退步；双方同为 300 ms 的小规模诊断也没有出现收益改善。保留代码和负结果，复用开关默认关闭，不推广到在线默认配置。

本轮从冻结提交 `89e71b8` 新建 `round5-decomposition-preparation-reuse` 分支。实现、回归、第四轮分解及事前机制协议在 `f5d11fb` 冻结，随后只运行固定开发快照机制实验。未重跑 HighDiv，未重新校准并发，未修改覆盖口径、观察保留条件或方向生成策略，未运行新的 120／300／900 **秒**端到端实验。

## 第四轮收益究竟来自哪里

完整分析见[收益分解报告](第五轮收益分解.md)。逐案例、种子、实际正式前缀，用 `raw_generator_index` 找到对应的原始前缀，计算：

`总差 = 同一次运行正式输出 − 同次原始前缀 + 同次原始前缀 − 独立 A/B 前缀`。

前一项是直接精修收益，后一项是原始序列差异；同时间分析的后一项还包含完成样本数量差异。覆盖整数计数先做精确恒等式检查，再转换为百分点。7,035 个正式精修前缀中有 6,126 个具备独立对照，909 个对照前缀缺失，缺失保留为空值；另有 45 组同时间分解。全部可比较恒等式成立。

| 比较位置 | 配对数 | 直接精修项（百分点） | 原始序列／数量项（百分点） | 总差（百分点） |
|---|---:|---:|---:|---:|
| 前 10 个 | 9 | +0.314125 | −1.617996 | −1.303870 |
| 前 50 个 | 7 | +0.069983 | −1.096913 | −1.026931 |
| 已有 120 秒终点 | 9 | 0.000000 | +0.376239 | +0.376239 |

前 10 个的退步主要来自 convert 的原始序列差异，尤其 seed 1 的 −33,606 bit；前 50 个主要来自 Bromberger seed 2 的 −1,900 bit 与 SMT_random seed 0 的 −3,847 bit。直接精修项没有造成这些前缀的覆盖退步，但其正收益也不足以抵消序列项。原始序列差异的原因没有被现有日志独立控制，不能笼统称为随机噪声；其正差也不能算作精修功劳。

实际 72 次替换全部发生在 Bromberger，其早期直接收益在终点被原始序列追平。第四轮平均终点 +0.376239 个百分点，全部属于原始序列／数量项。convert seed 1 另有一个完整原始模型但未完成输出的事务，以及 49,285 字节的正式输出截断尾行；均单独保存，不当作正式样本，不把其 48 bit 差额误记为精修损失。当前日志没有去重跳过造成的错位；`j≠k` 的实际原始前缀对齐已用合成回归验证。

## 最小实现及其适用边界

`SearchOptions::preparation_reuse` 默认关闭。开启时，safe polish 在同一内部模型下保留一次 `generate()` 调用内的区域、等式消元进度、方向、可行区间、目标池和游标，按候选批次消费。接受内部移动后立即结束旧栈，以新基点重建依赖模型、分支和观察条件的状态；没有把旧 Region 或 Reach 引用带到新模型中。

新版不按剩余步骤切分准备时间，`BudgetExceeded` 独立记录，不累计为已完成的无改善批次。旧版和新版均最多 6 批、24 个有效候选，每批 256 次目标尝试，整体上限 1,536 次；预算、批次和尝试上限共同约束退出。原公式验证、输出去重、原始新观察保留和输入模型回退不变。核心回归覆盖缓存生命周期、真实移动后的重建、局部零维状态、预算中断、部分批次保留和尝试上限。

**这不是候选序列完全相同、只删除重复计算的纯缓存消融。** 本次实现会消费一份有限的方向／目标流；流耗尽且没有内部移动时结束，不再为同一基点重新构建一轮。旧控制可以在后续短步骤重新生成方向／目标。方向生成函数没有改变，但继续消费现有流与重新生成一轮的执行过程不同。下文观察到的早退和候选数退化属于这一实现的边界，不能由此宣称所有准备缓存都必然无效，也不能仅凭准备时间下降宣称成功。

## 60 ms 主比较

事前约定见[机制实验协议](第五轮机制实验协议.md)。全部 12 个已有开发快照，种子 0／1／2，每个组合 3 次成对重复，共 **216 次调用、108 对**。一个工作槽先后执行同一配对，预先交错版本顺序；固定 15 槽，内部 OMP／BLAS 单线程。统计先对三次重复取平均，形成 **36 个快照×种子组合**。

预算从公式冷初始化前开始，包含恢复及验证前缀、初始化搜索、准备、评分、观察保留检查和最终原公式验证。实际额外覆盖减去输入模型本身已有收益。超期交付输入模型，收益记 0，潜在迟到收益另列。完整算法耗时后仍有证据序列化和退出成本，因此还记录逐 PID CPU 及完整子进程墙钟。全部计时完成后才启动独立原覆盖评测审计。

| 指标 | 旧版 | 准备复用版 |
|---|---:|---:|
| 每版调用数 | 108 | 108 |
| 平均实际额外覆盖（bit／调用） | 9.555556 | 2.731481 |
| 平均额外 bit／完整算法秒 | 176.686720 | 53.256614 |
| 平均额外 bit／子进程墙钟秒 | 133.029010 | 40.604233 |
| 平均完整算法耗时（ms） | 112.875445 | 111.344721 |
| 平均搜索准备耗时（ms） | 6.086137 | 3.639784 |
| 重复区域准备次数（合计） | 36 | 0 |
| 有合法候选的调用 | 23 | 21 |
| 合法候选数（合计） | 286 | 282 |
| 观察保留合格候选数（合计） | 161 | 87 |
| 初始化后已耗尽预算的调用 | 72 | 72 |
| 完整耗时超过预算的调用 | 74 | 74 |
| 迟到潜在额外 bit（合计，未计收益） | 0 | 74 |

36 组配对差的均值为 **−6.824074 bit**，中位数为 0；**0 组正差、33 组持平、3 组负差**。各案例先在自身组合内平均，结果如下：

| 案例 | 旧版额外 bit／调用 | 复用版额外 bit／调用 | 平均差 |
|---|---:|---:|---:|
| Bromberger | 28.666667 | 8.194444 | −20.472222 |
| SMT_random | 0 | 0 | 0 |
| convert | 0 | 0 | 0 |

这里平均完整耗时超过 60 ms 不是隐藏的较长预算成功结果：SMT_random 和 convert 的 72 次调用在公式／快照／搜索初始化阶段就耗尽预算，非可中断工作及最终核验仍按真实耗时计费，全部返回原模型且额外收益为 0。它们在本批没有进入 safe 搜索，不能把零候选解释为已完成搜索或重新证明局部锁死。Bromberger 的平均完整耗时为旧版 46.624 ms、新版 38.893 ms，但收益同时下降。

负差集中于三个组合：

- Bromberger/prefix-10、seed 0：每次旧版 +120 bit，新版 +1 bit；合法候选 15→2，步骤 6→2。
- Bromberger/prefix-10、seed 2：每次旧版 +102 bit，新版 +0 bit；合法候选 11→0，步骤 6→1。
- Bromberger/prefix-5、seed 1：一对双方潜在收益均 +74 bit，旧版 56.512 ms 完成，新版 60.616 ms 迟到，按事前规则计 0；另外两次持平。

前两个组合贡献总损失的约 90%。新版在约 21–32 ms 就结束，未触发总时间、尝试或候选上限，不能解释为单纯预算不足。结合有限流耗尽后不重启的代码路径，减少了重复准备，也减少了后续探索机会。另一部分损失来自最终交付截止条件。详见[独立复核](第五轮独立复核.md)。

首次合法候选的条件均值为旧版 26.514 ms、新版 24.697 ms，但分母分别只有 23／108 与 21／108，不能当作所有调用都变快。零候选、超期和初始化耗尽的调用全部保留在逐例数据及收益均值中。

## 单独的双方 300 ms 诊断

60 ms 中 **24／36** 个快照×种子组合满足“双方至少 2／3 次初始化后即耗尽预算”，触发事前声明的较长预算诊断；触发证据在启动前保存于 [longer_budget_trigger.json](../results/round5_preparation/longer_budget_trigger.json)。只用三例已有 prefix-1，双方都为 **300 ms**，共 **54 次调用、27 对**。未用新版 300 ms 与旧版 60 ms 进行收益对比。

| 案例（各版各 9 次） | 准备耗时 ms：旧→新 | 合法候选总数：旧→新 | 实际额外 bit／调用：旧→新 | 完整耗时 ms：旧→新 |
|---|---:|---:|---:|---:|
| Bromberger/prefix-1 | 28.041→19.782 | 180→180 | 0→0 | 58.568→48.554 |
| SMT_random/prefix-1 | 12.589→5.895 | 0→0 | 0→0 | 99.851→90.612 |
| convert/prefix-1 | 161.089→127.637 | 63→166 | 2.888889→0 | 301.200→310.857 |

这次全部调用都进入搜索。SMT_random 两边各 9 次确认当前 safe 区域零维；区域构建总数 18→9，重复构建 9→0，但额外覆盖仍为 0。复用减少的是重复证明成本，不是解决了锁死问题。

convert 是局部机制改善最明显的状态：合法且满足观察保留的候选从 63 增至 166；潜在额外覆盖总量从 177 增至 300 bit。然而新版 9 次全部在约 309.37–312.80 ms 才完成最终验证，实际收益全部归零；旧版 7 次超期，其余两次实际合计 +26 bit。旧版迟到的 151 bit、新版迟到的 300 bit 均不计入主收益。因此这里可说“准备更少、找到更多潜在可接受候选”，**不能说在同一总预算内交付了更多覆盖**。

全体 300 ms 调用的平均实际额外覆盖为旧版 0.962963 bit、新版 0；平均额外 bit／完整算法秒为 3.634325→0。9 个快照×种子组合为 0 正、7 平、2 负。该诊断不替代 60 ms 主比较，也不产生进一步筛选依据。

## 验证、数据与复现

Release 与 ASan/UBSan 各通过 **8 项 C++、31 项 Python** 测试；另通过配对聚合纯数据回归，检查零候选／失败保留、108 对归并成 36 组、单快照收益不能通过稳定门槛、审计内容变更必须被拒绝。泄漏检查保持开启，只有先前已独立复现的冻结 Z3 `lp::dioph_eq::imp::imp` 精确分配栈使用原有例外，不宣称外部库完全无泄漏。

两批 **270／270 调用**均通过独立原公式、冻结覆盖指标、观察保留、去重、输入收益扣除与截止回退审计。60 ms 计时／审计分别耗时 2.994／7.540 秒；300 ms 分别为 1.080／4.159 秒。逐 PID CPU 与墙钟另存，不把并行墙钟当作各调用成本。

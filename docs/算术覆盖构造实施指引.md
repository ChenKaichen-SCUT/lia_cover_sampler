> 在 Z3 已获得整数可行状态、即将完成算术最终检查时，利用当前 tableau 的整数保持自由方向生成少量候选原始赋值；以此前正式输出的原 AST 覆盖状态选择一个候选；由 Z3 内部提交，并经过正常检查后输出。

当前困难公式的实际算术状态中，有没有这个最小移动算子能够利用的自由度？

新方法是否同时改善固定时间覆盖和严格固定样本数覆盖，收益能否抵消全部新增成本？

1. 研究边界与已有证据
1.1 不再优化位置编号
已有固定第四位置消融没有稳定胜过固定第一位置或随机 1–4。保留 `position_immediate` 作为本轮外层基线；不要同时改变位置分布、Keep/Flip 概率、相位干预次数、查询授时策略或交付方式。[R1]
本轮的新因子是整数可行赋值的内部选择。它可能在不改变当前相关 Boolean/theory-atom 真值的情况下改变数值观察，但这一能力和收益都需要实际验证。
1.2 不把既有组件包装成创新
冻结的 Z3 已有 `int_solver::get_freedom_interval_for_column` 与 `shift_var`；项目已有一维整数模命中、等式保持方向和原 AST 覆盖评估。[R2][R3]
本轮要复用这些基础设施。潜在研究价值是：将原 AST 真实覆盖反馈可靠地连接到实际 LIA 求解状态，在受控成本下获得超出随机内部移动的收益。
“修改求解器内部”“加入覆盖评分”“生成更远的模型”都不能单独证明创新。HighDiv 已修改分支与相位并结合局部搜索；PanSampler 已使用历史 bit-value 分布引导求解并做 AST 候选评分；MeGASampler 已研究从种子模型构造可行区域。[R8][R9][R10]
1.3 第一版明确不包含
双列或多列联合移动、重新选基或额外 pivot。
多轮候选精修、额外 `solver.check()`、MaxSMT/Optimize。
新硬覆盖目标、永久排除零收益区域、覆盖冲突学习。
新的学习器、bandit、结构新颖性规则或运行期自调参。
为新方法免费提供历史模型、免费重放前缀或借用 HighDiv 的答案。
如果只有单列移动没有空间，应报告这个算子的能力边界，不能断言整个整数区域只有一个解。区域覆盖上界与可复用解释属于后续研究。

3. 三组实现与因果问题
三个正式配置使用同一个新 Release 可执行文件、同一份新 Z3 库，以运行参数选择模式。
标记	建议配置名	外层相位	新算术候选与选择
P	`phase_only`	冻结 `position_immediate`	新算术机制关闭，原生返回
R	`arith_random`	与 P 相同	统一覆盖盲候选生成器，从去重完整池（含 no-op）均匀随机选择
C	`arith_coverage`	与 P 相同	同一候选生成器，按覆盖分数选择
另实现仅用于机制诊断的 `arith_probe`：生成和分析候选，但不提交移动，不把影子候选当作正式模型。
3.1 候选生成不能偷用覆盖
R 与 C 的共同候选生成器不得读取 `seen0/seen1`、missing-bit 清单、历史收益或公式名称。列、项、bit 和目标值的选择来自当前结构与独立随机流。可以对某个结构选中的 bit 同时构造目标 0 和目标 1，但不能因历史缺哪边而只生成哪边。
否则 R 也已经使用覆盖反馈，C−R 只能解释排序增量，不能解释覆盖反馈相对盲目扰动的价值。本轮选用覆盖盲生成器，避免这个混杂。
两组使用相同候选上限和相同生成算法。**正式端到端 R 不必做它不需要的全部覆盖评分，不要人为烧时间使成本相等。**C 必须支付自己的真实评分成本。只有同状态诊断会统一评分整个候选池。
3.2 随机数流隔离
保持旧相位 RNG 及其消费位置不变。新增至少两个独立流：
`proposal_rng`：列顺序、结构目标、随机格点。
`selection_rng`：R 的候选选择；C 的非 no-op 平分选择。
从 seed、明确的 stream tag、query 序号派生；算法固定，不使用地址或平台不稳定的 `std::hash` 作为跨进程复现依据。新增流不能推进原 Z3 或相位机制的 RNG。
在相同状态、相同 proposal stream、相同固定工作量都完成且没有时间/累计额度截断时，R/C 的候选池必须一致；时间截断另行记录，不能承诺其逐项复现。完整轨迹分叉后状态不同，在线候选池不同是正常现象。相同 seed 不是求解器状态克隆。
4. 正确的内部接入与生命周期
4.1 必须保留原理论检查
冻结 `theory_lra.cpp::final_check_eh` 的关键流程为：
`propagate_core → make_feasible → check_lia → check_nla → assume_eqs → check_bv_terms → unsupported checks`。[R4]
推荐的接入约束是：**原有检查全部通过、原本准备返回 `FC_DONE` 时，才考虑本轮 hook。**这不是让你照抄某个固定行号；要在实际源码上验证该约束。
不能在 `check_lia` 成功后直接改值并提前返回 SAT，也不能把 `FC_GIVEUP/FC_CONTINUE` 改成成功。
4.2 一次查询最多一次机会
为每次外层 `check()` 建立 query epoch 和不随 backtrack/restart 回滚的 once latch：
第一正式模型之前不启用新算术机制。
第一次符合条件的最终检查点消费本 query 的机会。
只读构造候选，在影子原始赋值上评分。
选择 no-op 时不改内部状态，不额外要求复检。
选择非零移动时，校验 handle 与当前状态一致，内部提交一次。
失效所有旧 proposal，返回 `FC_CONTINUE`，让正常搜索和理论检查继续。
本 query 后续检查不再提交第二次移动。
外层正常获得 SAT 后，沿既有模型导出和交付路径处理。
`assume_eqs` 可能触发现有 `random_update`。保留此行为，并记录选中赋值在最终模型中的存活情况；不得为了保住预测收益而禁用正常检查或已有更新。
4.3 只读评分，内部提交
外部回调只能接收只读、生命周期明确的数值快照与候选描述，并返回 `candidate_id`。不得开放任意写 tableau 的接口。
评分不能对每个候选反复修改活求解器。先在影子赋值中求值，最后只提交一个候选。
回调中禁止递归 `check/get_model/push/pop/assert/Optimize`，也不要创建新 Z3 AST。跨回调保存 AST 时必须持有强引用；内部列号和借用指针不能跨 epoch 使用。
候选生成超时、取消、映射失败或 no-op 时，在没有修改活状态的情况下继续原正常流程。如果最终还未获得 SAT，不得将“待返回的影子赋值”冒充已经正式成立的模型。
4.4 提交失败与恢复
提交前完成所有可做的纯值检查；提交使用 Z3 原生值更新设施，并正确失效模型缓存与相关值缓存。
若立即不变量检查失败，只有在能够通过原生接口完整恢复当前列及依赖状态时才继续；否则保存 replay，将本次运行标为实现失败并停止正式筛选。不能仅恢复一个数值就假定 feasibility、changed-column 集合、缓存和 trail 都恢复了。
后续标准检查产生冲突、回溯或 UNKNOWN 时，交给标准求解流程处理。不要在已经发生其他理论修改以后，凭旧列号手工“回滚整个求解器”。
5. 最小数学合同：固定基下的整数保持移动
在当前已整数可行的状态，固定基和其他非基列。若 tableau 的规范化关系为：
[
x_B=b-Ax_N,
]
移动一个非基列 (j)：
[
x_j(k)=x_j(0)+h k,\qquad
x_i(k)=x_i(0)-a_{ij}h k,\qquad k\in\mathbb Z.
]
优先复用该冻结版本 `get_freedom_interval_for_column` 给出的区间和乘数 (h)。在满足当前整数列均为整数等前提时，相关有理系数分母的最小公倍数给出充分的整数保持步长。必须依据真实行符号与数据结构验证，不能把上述记号直接套进相反符号的实现。
将所有受影响列上下界转换为精确整数步长区间。若非基列合法取值为 ([\ell,u])，则：
[
L=\left\lceil\frac{\ell-x_j(0)}h\right\rceil,\qquad
U=\left\lfloor\frac{u-x_j(0)}h\right\rfloor.
]
无界端保留无界标记。严格界、无穷小和有理数必须精确处理；第一版对无法可靠具体化的状态直接 fallback。禁止浮点判断可行性、四舍五入整数或将原数学整数截断到 64 位。
每个 proposal 至少标识：
~~~text
query_epoch, lp_state_epoch, coverage_version, candidate_id
moved_column, original_column_value, proposed_column_value
integer_step, parameter_k
affected_columns, affected_original_variables
support_status, rejection_reason
~~~
LP 重建、internalization、push/pop、reset、回溯或其他会改变映射的操作必须使相关 handle 失效。
**上述合同仅保证所处理的线性关系、界和整数性，不自动保证整个 SMT 查询合法。**还要正确处理相关 atom 真值、disequality、完整赋值 blocker、assumptions、共享理论、模型恢复和原生簿记。
6. 原变量重构和纯值覆盖评估
6.1 使用原 AST，禁止把 LP 辅助列当正式指标
沿用 `Formula` 的原始节点和变量身份，建立：
`原始变量强引用 expr → 当前 enode/theory_var → LP 列或可靠重构表达式`。
原变量顺序与 LP 列顺序不是同一回事。预处理消元、别名和辅助列都要明确处理。原始 Bool 未确定、原始 Int 无可靠重构、需要猜测 model completion、存在未处理无穷小时，标记 `mapping_incomplete` 等原因并回退。
不能把未映射变量补零。第一版优先限定纯 Int/Bool、线性、原评测器兼容且能可靠重构的状态；这限制的是新机制，不应破坏原求解器对其他输入的行为。
6.2 评分器必须无求解器调用
`Formula::evaluate` 已有正确的短路和共享节点语义，但其 unsupported 分支可能调用 Z3 model API，不能把整个函数不加审查地搬到内部 callback。[R3]
建立纯数值评估路径，或抽取已支持操作的不可变求值计划：
Int 运算为任意精度数学整数。
Bool 节点只观察 1 bit，Int 节点观察低 64 bit。
AND/OR 保留原短路顺序。
整数 ITE 只访问当前分支。
共享 AST 节点去重。
未访问不同于访问后取零。
常量分母与原冻结指标一致。
未支持操作禁止触发回调中的 Z3 fallback。
第一版先全量、正确地评估候选。若之后做增量求值，必须处理短路访问变化与共享 DAG Reach，并与全量评估逐节点差分；不能只更新“数值变化节点”。
6.3 评分规则冻结
设查询开始前正式交付的观察历史为 (S)，候选的真实访问观察为 (O(m))。按字典序最大化：
[
\operatorname{score}(m\mid S)=
\bigl(\Delta C(m\mid S),\ \Delta O(m\mid S)\bigr).
]
其中：
(\Delta C)：按旧指标新增两种取值都已观察到的 bit 数。
(\Delta O)：新增 ((原AST节点,bit,值)) 数。
原生赋值作为 no-op 候选加入 R 和 C 的同一候选池。如果 no-op 的分数已达最大，C 选择 no-op；其余同分非零候选由独立 selection RNG 打破平局。
“没有新增 covered”不等于“没有新观察”。第一次观察到一个 bit 的一侧，可能没有即时 covered 收益，但仍是第二分量的有效进展。
所有候选只读同一个 (S)，不能候选 A 打分后先更新历史再打分 B。先完成并冻结整个覆盖盲候选池，随后才进入 C 的评分；评分不得反过来改变候选生成顺序或目标。
如果生成或合法性检查因时间/额度中断，R/C 均不提交部分池中的移动，记录 `pool_incomplete` 并走 no-op/原流程。C 如果未能评完冻结池，记录 `score_incomplete` 并返回 no-op，不把已评子集的最高分当作全池最优。池大小达到预先规定的候选数上限属于正常完成；这里的 incomplete 指未完成该次已经冻结的工作。
7. 覆盖盲候选生成器
7.1 冻结一个小的实现
首版最多扫描有限数量的非基列，读取它们在当前状态下的自由区间。构造少量：
非零邻近整数格点。
有限合法端点。
有界代表窗口中的随机格点。
按结构与独立随机流选中的少量原仿射项/bit 的 0、1 目标命中点。
以上各来源采用固定轮转顺序，避免某一来源永远占满全池。对结构选中的 bit 同时考虑 0 和 1，不读取哪一侧在历史中缺失。
以完整可重构原赋值身份去重；不同内部 proposal 恢复成同一个原模型时只保留一次。包含 no-op，记录每类候选实际贡献和所有截断原因。
先在代码中冻结具体顺序，再运行性能；不能看结果后换目标来源或上限而仍沿用同一实验编号。
7.2 复用现有一维模命中
如果某个原仿射项在这条方向上可可靠写成：
[
t(k)=\beta+\alpha k,
]
第 (q) 位取 1 等价于：
[
(\beta+\alpha k)\bmod 2^{q+1}
\in[2^q,2^{q+1}-1].
]
取 0 对应余数 ([0,2^q-1])。
复用 `include/math.hpp` 中 `count_bit_hits/find_bit_hit` 和 `src/line.cpp` 已有周期处理的纯数值部分，禁止为此创建 SMT/Optimize 子查询或逐点扫描大区间。[R3]
必须处理：
负数的欧几里得模与正确 floor/ceil。
(q=63) 所需的精确 (2^{64})，禁止 `1ULL << 64`。
(\alpha=0) 及某个 bit 沿方向恒定的情况。
无界区间按目标周期 (2^{q+1}/\gcd(\alpha,2^{q+1})) 选有限代表窗口。
在周期裁剪前排除零步长。
超大整数、分母或系数超限时回退。
只选有限代表窗口不意味着从无界模型集合均匀采样。某个方向无命中也不意味着该 bit 在原公式中不可达。

coverage 更新	只有最终模型正式及时提交时
新增求解查询	0
上述 5% 是新增算术模块自己的额度；既有相位模块的冻结额度保持原样，报告两者与总成本，不能只报告其中之一。2 ms 是可取消点检查的软限额，真实超支必须计入墙钟并记录，不能声称单个大整数操作可被无损硬中断。
如果一开始的映射/评估计划准备已经耗尽额度，记录停用并沿原流程运行，不把成本移到计时外。限额不足可以成为结论，不能在同批结果中途加码。
8. 外层采样、正式模型和完整查询合法性
继续使用原完整公式、持久增量求解、完整赋值阻塞和 immediate delivery。新机制不改变外层策略。
一个 `check()` 最多产生一个正式输出。内部分别构造或评分的十个赋值不是十个正式模型。不得输出原生模型后再把改进模型算成同一查询的免费第二个模型。
合法性对象为：
[
Q_t=F\ \land\ \text{当前 blockers、assumptions 及其他动态约束}.
]
只验证原 (F) 不够：候选可能满足 (F) 却返回了已阻塞模型。内部必须保持当前理论/分支一致性；正式输出仍需完整原赋值校验、去重和动态约束审计。
入池前（包括 no-op），用纯值路径确认候选满足原 F 与完整当前 Q_t，并核对所有受影响且已赋值的 relevant theory atoms 的真值和现有 disequality。完整赋值 blockers 可用精确模型身份集合检查；其他 assumptions/动态约束必须单独处理。需要时在进入 `check()` 前把动态约束编译为纯值检查计划，内部读取当前真值快照；这部分成本也计入机制。无法可靠表达或检查的状态必须 fallback。不能仅凭自由区间合法就把 proposal 标记为完整 SMT 合法，也不能等最终复检才排除 S2 中本来非法的“高收益候选”。不要为检查候选在 callback 中另开一次求解。
只有最终合法、不同、在截止前完整提交的正式模型才更新新机制的历史。影子预测、生成中间态、超时尾部和失败交付都不能更新正式 (S)。
记录生成与正式交付版本；虽然使用 immediate 模式，也不能将尚未交付的候选悄悄计入反馈。既有相位模块的输入语义保持基线实现，任何与新模块正式历史的差别要在机制说明中列出。

12. S2：同状态机制诊断
在一条真实基线轨迹到达的内部整数可行状态上，只读提取统一候选池，保留原生 no-op 作为正式求解路径。最多记录每会话前 32 个 eligible 状态；候选构造与评分也受预算限制。
对每个完整分析的候选池计算：
no-op 的 (\Delta C,\Delta O)。
随机选择期望：去重池中各候选分数的算术平均。
C 的选择结果。
候选池内最高分及比 no-op 的差。
候选生成、原赋值重构、合法性确认与评分成本。
池未分析完要标记 partial，不能把已检查子集的最高分称完整池最优。这里的最好值只是测试候选池内最好，不是整个可行区域或公式的上界。
每次候选池评分期间冻结同一份历史。影子候选不能进入 seen、正式输出或 blocker，也不修改活求解器，所以这项诊断不需要对每个候选做一次活状态回滚。probe 正式返回的原生 no-op 模型仍按 P 的正常规则完成交付、更新历史并添加 blocker，下一查询使用正常推进后的历史；不能把整次会话的历史永久冻结。probe 运行包含额外开销，不能把它的时间曲线当作原 P 的正式性能。
S2 默认晋级门槛
同时满足：
两个主公式均实际进入目标 hook；如果其中一个始终无法接入，报告适用性缺口，不进入大批筛选。
至少两个公式各取得至少 10 个完整、可重构、可独立检查的候选池。
其中至少一个为 SMT_random 或 SMT_real。
在这些公式上，均存在候选比 no-op 的 ((\Delta C,\Delta O)) 严格更好；同时覆盖选择的池内 covered 收益至少在一个主公式的多个状态中高于随机期望。
没有正确性错误；成本和额度停用信息完整。
这是检验“值得支付后续实验成本”的弱门槛，不是性能成功标准。如果 30 秒没有取得足够状态，结论为证据不足或接入/初始化受限；不要伪称整个方向无效，也不要自动扩大到 900 秒。
如门槛失败，仍交付完整 S2 报告，指出是映射、自由度、可观察性、候选设计还是时间预算限制。
13. 首模型与状态归因
本轮全部新算术配置在第一正式模型之后启用。记录 P/R/C：
公式、求解器类型、seed、参数与 API 调用顺序。
首次成功前 SAT/UNKNOWN 和授时序列。
首模型完整身份、生成和正式交付时间。
算术机制真正开始准备与启用的时间。
即使代码在首模型前相同，墙钟超时、资源争用和授时路径仍可能导致首模型不同。**不得删掉这些 seed，也不得将其差异归因于尚未启用的算术机制。**完整运行比较保留这些差异；同状态机制证据主要来自 S2。
不要将“重建 F 加同一个 blocker”“相同 seed”或“相同第一模型”描述为复制了 learned clauses、tableau 和求解器内部状态。若另外实现确定性操作额度的初始化控制实验，单独标注语义与成本，不替换主要完整策略结果。
不向任一组免费注入历史首模型或前缀，也不扣掉新方法的准备时间后再与 P 的完整时间比较。
14. 机器资源与计时
14.1 并行
根据实际 CPU affinity 和物理核拓扑生成计划，默认最多 6 个采样进程，占用不同物理核，至少为监督与系统保留资源。
同一公式/seed 的 P/R/C 作为完整配对组；有条件时在不同物理核同批运行，按预先固定的轮换平衡 CPU 和启动顺序。可同时运行两个三配置组。资源不足时减少并发，不能改成把 15 个逻辑 CPU 当 15 个独立物理核。
所有采样均单线程；监督器和 Z3 超时辅助线程的亲和性需要记录。采样期间不同时编译、运行 sanitizer、压缩归档或并行审计。
14.2 完整墙钟
120 秒从监督器启动任务前的单调时钟起计，包含：
读取、解析、初始化、纯值计划构造、求解、候选提取、评分、提交、正常复检、验证、日志、去重和正式交付。
截止时停止生成；最多允许预先冻结的短清理窗口，建议 2 秒，但该窗口内完成的模型不得进入 120 秒结果。按完整交付完成时间认定及时性，不按开始写文件时间或内部发现模型时间。
复用旧 runner 的冻结、进程组终止和审计逻辑，但去除旧固定 15 路的调度假设。设置并记录逐进程内存上限、全机可用内存底线及资源异常处置；不要在资源不足时隐式重试有利的任务。
15. S3 的指标与统计
15.1 双主目标
时间主指标是原覆盖口径的 `C(120s)`。样本质量主观察点预先固定为严格前 100 个正式模型的 `C_100`，同时重点监视早期 `C_10`。
时间点固定为 1/5/10/30/60/120 秒，计算精确阶梯 AUC。样本前缀固定为 1/2/5/10/50/100/1000。
达到 100 或 1000 前不得用当前最后模型代替。未达到记 NA，报告每组三项：
达到该前缀的会话数。
达到所需时间。
每个配对双方达到/未达到的状态。
只有完整配对才能计算严格前缀差；完整配对结果必须与全部达成情况一起展示。若所有配置都未达 1000，明确本轮没有回答前 1000。
15.2 配对表
至少输出 C−P、C−R、R−P。每公式分别展示 7 个原始 seed 差值、均值、中位数、胜/平/负、最大退步。保留零模型、超时、停用与无触发会话。
跨公式比较使用：
[
d_{f,s} = 100\frac{C^{new}{f,s}-C^{base}{f,s}}{B_f},
]
其中 (B_f) 是该公式冻结可评价 bit 总数，单位为覆盖率百分点。先在每公式内汇总 seed，再对公式等权汇总；不直接把大公式的 bit 差压过小公式。
seed 不是新公式，模型/查询/候选不是独立实验重复。四个旧开发公式上的描述性改善不能包装成泛化显著性证明。若给区间，说明重采样层级与小样本限制。
15.3 辅助解释
报告：
正式模型数、首模型时间、各前缀达成率。
候选空间支持率、非零合法移动率、提交率、no-op 率。
预测收益与最终正式收益，候选存活。
新观察与 covered 分开。
新增成本、额度停用时刻、SAT/UNKNOWN 及完整 query 成本。
真实顺序下的 0、1–2、3–9、10–99、100+ bit 收益分箱。
所有收益分箱均基于实际输出顺序的边际变化，不能把多个同一冻结状态下独立计算的收益相加。变量变化数、组数、数值距离仅作描述，不代替正式覆盖目标。
16. 筛选晋级与停止条件
下列门槛在 S3 前冻结，不能看结果后降低。它们只决定是否值得开展更大确认，不代表论文级证明。
16.1 正确性门槛
所有正式输出合法、不同、及时；独立覆盖重放一致；无状态损坏或预算外计入。任一失败即“实现失败”，不进入性能排名。
16.2 默认继续研究门槛
对 C−P 和 C−R 两个比较分别满足：
四公式等权的 `C(120)` 归一化均值差为正。
至少 3/4 公式的 `C(120)` 配对中位数为正。
严格前 100 的可比较数据至少覆盖 3 个公式；每个计入晋级的公式，P/R/C 三组共同完成前 100 的同一 seed 集合至少为 6/7。在该共同集合计算 C−P 与 C−R，对应等权差为正，且至少 3 个公式的中位数为正。两两完整配对仍全部展示，但不能各挑不同子集通过晋级。
C 的前 100 达成率逐公式不低于相应对照；如果对照能达到而 C 因变慢未达到，不能靠删除配对或跨公式相抵通过门槛。
前 10 覆盖与 120 秒终点没有严重退步：默认将某公式中位数相对该对照的对应中位覆盖下降超过 5% 视为严重；对照为零时不计算相对百分比，改报绝对结果。
机制有实际调用和提交，S2 提供同状态下的正向选择证据，且没有未解释的构建、参数或外层策略差别。首模型不一致时，分别报告完整策略性能与 S2 机制证据，不把初始化差异归因于算术干预。
若严格前 100 完整度不足，判断为“同样本目标证据不足”，不得宣布双目标成功；可以据已观察结果提出下一轮需要的独立预算，但本轮不自动延长。即使通过上述门槛，也必须明确：固定时间比较覆盖四个开发公式，严格前 100 的证据具体覆盖哪些公式、多少共同配对；其余公式的该前缀结论仍为未知。
16.3 必须采用的结论类型
观测	可支持的结论
C 同时胜 P 和 R，时间与严格样本口径都通过	初步支持继续研究，尚需新实例确认
R 与 C 都胜 P，C 对 R 不稳定	发现内部数值扰动收益，未证实覆盖选择额外价值
C 胜 R，但不胜 P	有局部选择价值，新增开销或轨迹损失抵消收益
C 样本质量提高、同时间退步	当前双目标未满足，应审查成本
只在一个公式明显提高	实例特定线索，不能称普遍机制
大量 mapping/unsupported，hook 没有真正工作	工程接入或支持率不足
hook 工作，但单列候选无空间	当前算子能力不足，不等于整个区域穷尽

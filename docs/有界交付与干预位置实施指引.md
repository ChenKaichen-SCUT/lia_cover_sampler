

# 下一阶段任务：有界交付排序与原生干预位置的分离实现和验证

## 1. 基点、目标与不变项

基于仓库：

```text
ChenKaichen-SCUT/lia_cover_sampler
```

冻结提交：

```text
ba9cca4
```

新建分支：

```text
native-position-bounded-delivery
```

本轮实现两项独立功能：

**A．有界交付排序：** 在已经真实生成的少量合法候选中，按当前正式覆盖选择交付顺序，验证是否改善少量正式样本的互补性，同时量化等待和维护成本。

**C．干预位置变化：** 保持每次查询最多一次Keep／Flip、概率不变、原式不变，仅将干预位置从“第一个支持对象”改为“事先选定的第几个支持对象”，验证是否产生更有价值的新观察。

本轮不启用在线反馈学习，不增加硬目标、assumptions、投影、整数选择编码、MaxSMT或新的重启策略。

保留原来的 `native_random_one`、历史二进制、结果和报告。不修改 `ba9cca4` 的离线结论，不将其选出的模型编号、HighDiv见证或缺口清单提供给新算法。

所有新增规则、参数、实验计划先冻结，再运行。

## 2. 使用四配置设计，避免把不同收益混在一起

| 配置 | 干预位置 | 交付策略 |
|---|---|---|
| `first_immediate` | 第一个支持对象 | 立即交付 |
| `first_batch` | 第一个支持对象 | 有界批次内排序 |
| `position_immediate` | 预先随机选择支持对象序号 | 立即交付 |

## 3. 首先拆开“生成状态”与“正式交付状态”

### 3.1 新增两个明确状态

```cpp
struct GenerationState {
    // 全部及时完成验证的不同合法候选。
    // 原始候选序号、完整身份、累计观察。
    // 最近生成模型及生成侧的查询统计。
};

struct DeliveryState {
    // 已经及时写完并正式交付的模型。
    // 正式输出序号、完整身份、累计观察。
};
```

两者都使用原始 AST 与冻结覆盖定义，但更新时间不同。

**生成状态**在候选完成完整赋值、原公式验证、观察计算并具有可追溯记录后更新。

**交付状态**只能在该模型完整写出、取得有效及时提交收据后更新。

生成状态中的模型不是正式输出，不能直接计入用户得到的覆盖。

### 3.2 阻塞依照生成，而不是交付

每个合法、不同的候选一旦生成，应按原规则加入完整原赋值阻塞，不必等它被交付。

否则，同一候选等待交付期间可能被反复生成，或者交付重排改变了阻塞顺序，把“输出优化”变成另一种搜索机制。

暂存模型必须具有不可变的完整赋值和观察结果。不要保存一个以后随求解器变化的 model 对象引用。

### 3.3 生成器只读取生成侧历史

下一次原生相位策略准备时，使用：

```text
generation_version；
最近生成的合法模型；
生成侧累计观察；
生成侧近期查询与成本。
```

不要根据批次里已经交付了几条，改变下一次生成的随机数、干预对象或查询策略。

第一份合法模型在四种模式中都立即交付，之后才启用相位干预和批次功能。

本轮不使用学习器；生成侧记录原有特征时，也必须与交付侧隔离。

### 3.4 添加状态不变量

任何时刻均应满足：

$$
O(S_{\mathrm{delivered}})
\subseteq
O(S_{\mathrm{generated}}).
$$

每当候选批次全部排空，应满足：

$$
O(S_{\mathrm{delivered}})
=
O(S_{\mathrm{generated}}),
$$

前提是没有截止、外部取消或写出失败造成的未交付尾部。

分别检查两条轨迹的边际累计恒等式，不能只比较最终 covered 数量。完整 seen0/seen1 不一致，即使 covered 数相同也必须报错。

### 3.5 不承诺真实限时下生成序列完全相同

状态分离能够避免“因为输出顺序不同而主动改变生成输入”，但批次评分、写出和等待管理仍消耗时间，可能改变剩余查询预算及限时搜索轨迹。

因此：

- 在固定查询次数、固定授权和无墙钟截止干扰的回归中，验证相同位置策略下生成序列一致；
- 在真实限时实验中，不强行要求候选流完全一致，而是完整计入这些开销并实际比较。

## 4. 实现A：有界、无丢弃的批次交付排序

### 4.1 首版只做局部排序，不做复杂候选池

建议新增：

```text
include/bounded_delivery.hpp
src/bounded_delivery.cpp
```

首版统一参数：

```text
批次容量 B = 32 个不同合法候选；
刷新触发时间 W = 0.5 秒；
每次刷新完成后排空整个批次；
第一份合法模型不等待，立即交付。
```

这些是本轮提出的保守初始参数，不是从“第37个模型在2.866秒出现”反向拟合出来的最优设置。禁止按公式名设置不同容量或时间。

候选满足以下任一条件时，开始刷新：

```text
容量达到32；
最早待交付候选已经等待0.5秒；
会话接近截止；
生成器正常耗尽；
生成过程准备结束。
```

在等待期间继续正常求解，不主动休眠，不为了凑满32个停止输出控制。

### 4.2 0.5秒是刷新触发阈值，不是假装可抢占的硬上限

当前一次 `check()` 可能跨越刷新时刻。首版在查询结束后立即检查并刷新，不为了批次定时器修改原查询授权，也不额外中断求解器。

记录真实候选等待时间，并明确：

> 刷新可能因正在执行的求解调用而推迟，0.5秒不是每个候选绝不超过的交付时限。

超过阈值的原因和实际延迟必须出现在报告中。不能在候选生成时就提前填写正式交付时间。

### 4.3 刷新时按当前正式覆盖重新评分

对批次中的每个候选 \(m\)，计算：

$$
g(m,S)=f(S\cup\{m\})-f(S),
$$

再计算其新增0/1观察数。

按以下顺序选取下一条交付模型：

```text
真实新增 covered bit 更多；
相同时，新增0/1观察更多；
仍相同时，优先较早生成的候选。
```

每交付一个模型，立即更新正式覆盖，再重新计算剩余候选的边际收益。

不能在批次开始时一次排序后直接输出到底，因为前一个模型可能使后续候选的收益发生变化。

复用候选已经验证的完整观察位图，避免反复对原公式调用求解器或重复做昂贵解析。

### 4.4 所有候选都交付，不因为零收益而丢弃

首版刷新时输出批次全部模型，包括剩余覆盖增益为零的候选。

这样做是为了明确隔离**顺序效果**，避免通过减少输出数量或丢弃首次观察来美化结果。

还必须处理“当前 covered 增益为零，但具有新单侧观察”的情况；它可能与后续模型共同形成覆盖，不能作为无用模型删除。

对每个完整排空的批次，独立检查：

$$
O(S_{\mathrm{before}}\cup B)
=
O(S_{\mathrm{after}}).
$$

这是集合保持检查，不是对贪心排序最优性的证明。

### 4.5 限制排序成本

首版批次最多32个，允许使用简单的真实边际重算，不立即实现复杂的近似评分器。

增加固定保护：

```text
单批排序维护超过20毫秒：
剩余候选按原到达顺序交付。

整场新增交付管理成本超过总预算5%：
排空当前批次，后续改为立即交付。
```

保护触发和实际越界成本必须记录。原本各配置都需要承担的模型写出成本，与新增排序维护成本分开统计。

这只是控制额外风险，不能声称正式墙钟覆盖不会下降。

### 4.6 截止前处理

四配置统一为最终交付保留100毫秒，不给批次配置额外时间。求解授权以相同的内部生成截止为依据。

接近截止时停止启动新查询，排空已生成候选。排序来不及时退回FIFO，不能继续追求更优顺序而丢掉已有可交付模型。

若仍有未及时交付的模型，保存为尾部未交付候选，计入生成侧但不计入正式结果。900秒之后写出的模型不能倒签进入900秒覆盖。

## 5. 实现C的候选机制：只改变一次干预的位置

### 5.1 不改变相位概率与干预强度

继续使用：

```text
每次 check 最多一个决策机会；
该机会 KeepNative / FlipOnce 各50%；
最多检查前32个原生决策；
首模型之前不干预；
不修改原生决策变量选择。
```

不增加多次翻转，不同时改重启、查询时限或学习器。

当前补丁的回调已经支持“跳过本次机会后继续寻找”，因此应优先利用现有接口扩展项目侧位置规则，而不是大规模重写Z3。需要同步更新回调返回值说明和日志，避免把“有意跳过位置”误标为“不支持原子”。

### 5.2 事先选择目标位置

在 `position_*` 模式中，每次正常查询开始前，从：

$$
K\in\{1,2,3,4\}
$$

均匀抽取一个目标序号。

在前32个原生决策范围内，按照实际遇到的**不同、支持、可正常决策的原子**计数。到第 \(K\) 个对象时，执行一次Keep／Flip。

```text
目标序号之前：保持原生相位；
到达目标序号：选择Keep或Flip，耗尽本次机会；
之后：不再干预。
```

同一个原子因回溯再次出现，不重复计入“不同支持对象”序号；计数及额度不因内部restart或回溯而重置。

若查询结束前没有遇到第 \(K\) 个对象，记录 `target_not_reached`，本次不干预。不能在事后把机会补给第一个对象，也不能重新求解一次。

### 5.3 随机数隔离

位置随机数使用独立流，不能消耗原有Keep／Flip随机流或Z3原生随机流。

`first_*` 模式固定 \(K=1\)，并保持原有动作随机数的调用规则。交付策略不能调用位置或动作随机数。

记录目标序号、实际支持对象序号、原生决策序号、对象身份、动作和概率。

### 5.4 说明这个对照的边界

随机选择位置可能导致实际干预次数下降，因为某些查询只有一个或两个可用对象。

因此，报告必须同时展示：

```text
目标位置分布；
实际到达分布；
未到达比例；
Keep／Flip数量；
真正改变了相位的次数。
```

如果位置版更好，首先只能说明**这套位置选择策略整体更有效**。不能在没有进一步对照时，将收益全部归因于“更晚的原子更有价值”，因为干预频率也可能改变。

本轮不再增加第五种频率匹配配置，先把这个限制准确报告。

### 5.5 保留一般性

不得使用历史HighDiv缺失bit、模型编号、某个变量名称或已知见证选择位置。

相关模型距离、变化变量数和分支变化只用于事后诊断，不作为本轮新奖励目标。已有结果明确显示“大范围变量变化”也可能完全没有新增覆盖。

## 9. 必须同时报告“生成效果”和“用户实际拿到的效果”

### 9.1 主指标以正式交付为准

正式主指标是：

$$
f(S_{\mathrm{delivered}}(T))
$$

以及：

$$
f(\text{前 }k\text{ 个正式交付模型}).
$$

固定报告：

```text
时间：1、5、10、30、60、120秒；
样本数：2、5、10、50、100、1000。
```

未完成前缀保留NA。不能用已生成但仍在批次中的候选充当已交付覆盖。

### 9.2 原始生成侧也要完整报告

同时报告：

```text
原始不同合法候选数；
原始候选前k覆盖；
生成侧累计覆盖；
正式输出数与覆盖；
等待时间的中位数、p95和最大值；
第k条交付时已经生成多少候选；
批次评分和维护成本；
截止时未交付数量及其观察差额。
```

如果正式前10个样本更好，但这时已经生成了50个候选，必须明确写出50个候选的全部成本。

**只改善交付前缀而没有改善原始候选质量，称为“交付排序收益”，不能称为“生成器变强”。**

### 9.3 对A的判断

重点检查 `first_batch` 相对 `first_immediate`：

```text
前10、前100个交付样本是否更互补；
取得这些样本的实际时间是否增加；
固定时间正式覆盖是否被等待和评分拖累；
收益是否仅在个别批次边界出现；
全部模型最终排空后覆盖是否一致；
是否出现未交付尾部造成的信息损失。
```

一个交付策略可以改善相同样本数，却损害相同时间覆盖。必须报告这种权衡，不能只展示有利的一面。

### 9.4 对C的判断

重点检查 `position_immediate` 相对 `first_immediate`：

```text
是否更早出现正增益模型；
原始候选在同数量下是否更互补；
固定时间生成及交付覆盖是否增加；
是否出现原基线本次没有获得的观察；
新增观察是否抵消了其他观察的丢失。
```

在采样结束后的独立分析中，可以使用 `ba9cca4` 保存的HighDiv缺口集合检查新轨迹补齐了多少已知缺口。

对于没有同seed历史参考的新seed，使用预先冻结的共同缺口集合并明确口径，不能临时挑最有利的参考。

历史缺口分析只作辅助证据。**新版本补齐几个旧缺口，却同时丢失更多其他覆盖，不算总体改善。** HighDiv目标也不是唯一目标，新获得的其他合法覆盖同样应统计。

历史参考模型和缺口文件不得被在线可执行程序读取。

### 9.5 高原要分生成与交付两种

批次等待可能造成“交付覆盖暂时不涨”，即使内部正在生成有用候选。

因此分别统计：

```text
生成侧无新观察、无covered增长的时间；
交付侧无增长的时间；
单纯因待交付批次造成的延迟；
两者同时停滞的区间。
```

不能把批次突然集中交付造成的大跳跃解释为求解器突然生成了一个特别好的模型。

## 10. 决策规则：分别保留有效部分，不强求组合版获胜

先冻结以下判断框架。

### 交付层

如果同数量正式样本的覆盖提高，但等待导致固定时间覆盖反复下降，结论是：

> 有前缀压缩价值，但尚未满足“同时间也更好”。

如果收益仅来自事后可见的候选或错误时间戳，直接判实现不合格。

如果本轮32容量、0.5秒触发规则没有收益，只能否定这项具体实现，不能据此推翻已证实的离线A类潜力。

### 生成层

如果改变位置在至少一个公式上出现2/3 seed的真实时间覆盖正差，且不是通过未交付候选计分得到，可保留为有限正面信号。

若两个公式均出现重复正差，并且同数量原始样本没有明显系统性退步，则值得进入更长预算验证。

若主要变化只是干预次数减少，而覆盖改善，报告这一事实；不要无证据地宣称后续原子本身更优。

### 组合层

不预设 `position_batch` 必须成为最终版本。可能出现：

```text
只保留位置变化；
只保留交付排序作为可选功能；
两者均有效且组合有效；
分别有效但组合成本过高；
两者都没有净收益。
```

按数据选择，不能为了保留工作量强行组合。

模型吞吐下降不作为一票否决，但必须由更好的实际覆盖补偿。

## 11. 条件满足时，再做一次冻结900秒验证

只有120秒实验出现跨两个实例的明确正面信号，才进入下一阶段。最多选择**一个统一配置**，不能random用一种、real再定制另一种。

冻结代码和参数，使用未参加120秒筛选的seed 3、4：

```text
2个实例 × 2个seed × 2个配置
= 8次900秒会话
```

两个配置为：

```text
first_immediate；
选出的唯一候选配置。
```

这组实验用于确认改进是否持续到长预算，而不是只把已有覆盖提前交付。

若120秒结果仅支持单公式或存在明显权衡，完成报告后停止，不自动执行900秒，不加大批次容量、等待时间或可选干预序号寻找正例。

本轮不重跑HighDiv。历史值和历史前缀继续作为描述性参考；即使新数值超过历史值，也不能宣称已完成同条件、跨种子的HighDiv优势证明。

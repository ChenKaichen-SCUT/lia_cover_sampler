# 生成与正式交付的两个状态

新入口`native_delivery_sampler`由位置策略和交付策略两个开关组成；旧`native_feedback_sampler`入口和历史二进制、库、结果继续保留。查询等级、Keep/Flip动作概率、原子分类、原公式和完整模型阻塞不变。所有配置统一预留100ms交付时间，这是本轮对真实墙钟截止的共同变化；不声称与旧入口最后100ms行为相同。

`GenerationState`包含已经完成完整赋值、原公式验证、一次观察求值和候选记录的及时不同模型，持有最近生成的完整赋值、身份集合与完整seen0/seen1。候选内容存入`shared_ptr<const SavedCandidate>`，只有不可变原赋值、序列化文本和原AST观察位图，没有活的Z3 model引用。候选记录与生成收据写完后才取得ready时间，随后提交生成覆盖，并按原完整no-good阻塞。阻塞发生在任何批次选择之前，单独有blocks记录。

`DeliveryState`只在完整模型及写出收据完成且及时后更新。`deliveries.jsonl`保存模型；`delivery_receipts.jsonl`记录模型完整写出事件，flush后测得实际提交完成时间；`delivery_commits.jsonl`保存该时间与及时判定。晚到输出不更新正式状态，也不倒签时间。每条正式模型绑定真实生成query/index，而非当前刷新的查询。生成日志同样有候选、收据和后写的完成时间证明。

生成器的下一次prepare只读生成覆盖、last_generated_model、生成版本与生成侧近期成本；交付排序不调用任何随机数。生成侧成本特征与查询控制排除明确测得的交付处理段；完整会话墙钟仍包含所有加载、初始化、失败查询、阻塞、写出和管理。这是状态隔离所需的时间记账变化，非学习奖励变更，学习始终禁用。真实限时下管理开销会减少剩余查询授权，因此只有固定额度回归要求相同生成流，性能实验不要求逐模型完全相同。

批次的第一模型立即交付；之后最多32，容量或最早候选等待0.5秒触发。每交付后重新评分完整位图；顺序为covered、新观察、早生成。正常耗尽/测试查询结束且有时间时仍进行逐次排序；接近总截止则直接FIFO保全交付，成本超过20ms也把剩余改FIFO，管理成本达到5%后永久立即交付。所有零增益候选保留。0.5秒不是可抢占承诺；查询调用起止、实际等待、触发延迟均保存。

每个完整排空批次检查完整观察集合守恒；每次正式交付检查其观察是生成观察子集；两侧分别检查covered及观察边际累计。无尾部时最终完整状态相等。超时、外部取消或写出失败的未交付尾部单列。

位置扩展使用原NativePhaseFeedback分类/随机动作实现。第一位置不增加动作RNG调用。位置模式采用另一个mt19937_64，在每个有资格的prepare中预选1–4；按前32个原生正常决策中不同支持AST编号计数；重复遇到不加序号。原子引用由已有缓存持有，跨回溯/restart不重置本次seen/机会。遇到目标后Keep也消费机会。未到达不补发，不再check一次。已有回调ABI的0实际表示“保留原相位并继续寻找”，项目侧现在区分`position_before_target`、`duplicate_supported_atom`与不支持原因；1/2消费唯一机会，3停止。历史Z3补丁文件和二进制不改写。传播和特殊接口仍由既有Z3钩子屏蔽。

独立审计从原始完整赋值重新求值，分别按生成和交付顺序恢复状态，核对每条收据、阻塞顺序、原query、批次可用性、真实重新评分、FIFO切换、完整位图、两套RNG及尾部。历史HighDiv观察与缺口只由采样结束后的分析脚本打开，在线入口只有公式/配置/预算/seed/输出目录五个输入。

构建与正确性检查（不与性能采样并行）：

```bash
cmake -S . -B build/native_delivery/release -DCMAKE_BUILD_TYPE=Release \
  -DLIA_ENABLE_SOFT_PHASE=ON -DLIA_ENABLE_NATIVE_FEEDBACK=ON \
  -DZ3_PREFIX="$PWD/dependencies/z3-native-feedback-phase/install"
cmake --build build/native_delivery/release -j15
LIA_NATIVE_DELIVERY_BINARY="$PWD/build/native_delivery/release/native_delivery_sampler" \
  /tmp/lia-highdiv-frozen/venv/bin/python3 scripts/test_native_feedback_build.py \
  --build build/native_delivery/release --out results/native_delivery_validation/release
```

ASan/UBSan使用独立`build/native_delivery/sanitize`与只读既有`install-sanitize`依赖，沿用原已知Z3泄漏的精确LSan抑制，无新增抑制。测试程序`bounded_delivery_replay`只能读固定赋值，没有求解生成路径；FIFO参考与有界排序使用相同历史片段及同一批次成员，只作为功能证据。

完整自动流程由`scripts/run_native_delivery_workflow.py`顺序运行曝光、审计、筛选、审计以及符合冻结条件时的唯一900秒验证。任何采样或审计错误都会停止并保存证据，不自动重试或调参。`--push-results`明确启用结束后的结果提交和推送；流程不在采样期间审计或构建。运行前必须存在绑定当前代码与二进制的`results/native_delivery_validation/summary.json`。

# 第六轮：覆盖目标先行与冲突引导变量块扩张

本轮结论是**停止扩大实验，暂不接入 A/B 或短预算筛选**。独立的 `coverage_block_generator` 已实现并通过回归；在双方相同的 60 ms 动作预算下，平均新增覆盖从 321.24 提高到 885.00 bit，但改善只出现在 Bromberger/prefix-1。该例 prefix-10 退步，另外两个案例均没有正收益候选；首次正收益时间及包含初始化的完整会话成本也未降低。结果不足以支持“小变量块及冲突扩张能够稳定、更便宜地生成高覆盖模型”。

代码从冻结提交 `5ed367c` 建立分支 `round6-coverage-block-generator`，实现、回归和[事前协议](第六轮机制实验协议.md)于 `41227d1` 冻结，之后才执行固定机制实验。没有修改 polish、准备缓存、复杂调度、覆盖计算或冻结 A/B，没有重跑 HighDiv，没有启动新的端到端实验。

实现位于 [coverage_block_generator.cpp](../src/coverage_block_generator.cpp)，独立接口见 [头文件](../include/coverage_block_generator.hpp)，常驻会话入口见 [coverage_block_probe.cpp](../src/coverage_block_probe.cpp)。两侧共用现有 [Global::query()](../src/global.cpp) 的 Reach、精确无界整数 LIA bit 编码及目标缓存；本轮新增的是变量固定 assumptions、局部冲突作用域识别、有界协同释放和全局回退。没有将“给求解器添加覆盖目标”作为新机制或独立创新。

两侧使用相同的目标池、主目标选择、相关目标包、模型排除、验证、评分和检查点规则。主目标优先已有相反观察的原 AST bit，并单独记录首次观察；查询始终保留完整原公式 F。变量块模式从目标及 Reach 依赖出发，只沿相关变量的祖先有界查找全局必要等式作为释放提示。分支内等式不会被提升为全局约束，Boolean 分支变量可以释放。

固定变量与目标、种子排除分别使用新鲜 assumptions。固定条件参与的 UNSAT core 触发按原变量索引顺序释放至多两个变量，并有界补入必要等式的协同变量。依赖操作、块大小、扩张次数及查询次数均有上限，到界或受限查询无法完成时允许在同一剩余预算内回退全局。只有不含固定／排除条件的目标 core 才能进入全局目标缓存；Unknown、Timeout、资源耗尽和预算退出都不构成不可达证明。每个动作的种子固定不变，assumption 标签与所属求解器绑定，旧动作的条件只留下未激活的蕴含约束，不限制后续动作。

每个候选通过完整 F、目标 Reach／bit、正式输出去重和种子不等检查后，对**全部冻结正式覆盖 S**评分。候选是新增样本，收益为 Δ(x|S)，不减去种子自身的收益，也不要求保留种子的观察。内部候选与三个重放动作均不更新 S。少量相关缺口可以加入目标包；冲突只删除参与冲突的目标，已有 SAT 见证保留。动作共享一次总预算，验证及落盘预留 20%（至少 2 ms）；只接纳截止前完成检查点写出的模型，后续失败不能抹去及时见证。

合成回归包含用户给出的 `(x+y=10) ∧ (x=0 ∨ x=10)`：从 `(0,10)` 得到 `(10,0)`，命中 x 的第 1 位相反值，且离开原安全区域。其他用例覆盖 Boolean Reach 切换、必要等式协同释放、局部 core 扩张与缓存隔离、真实资源耗尽与注入 Unknown、包冲突保留见证、后续超时保留检查点、全局回退及超过 64 位的负整数。Release 和 ASan/UBSan 均通过 **9 项 C++、37 项 Python 测试**。泄漏检测开启，仅沿用冻结 Z3 已知 `lp::dioph_eq::imp::imp` 外部泄漏的既有 suppression，未扩大排除范围。记录见 [构建与测试清单](../results/round6_dev/builds/validated.json)。

性能实验仅复用第三轮的六份开发快照：Bromberger、SMT_random、convert，各取 prefix-1 和 prefix-10。每状态三个 solver seed、两次配对重复；每会话复用同一 F、S、种子和 Global 求解器做三个动作。共 **72 会话、216 动作、108 对动作**，双方都是 **60 ms、最多 6 次查询、目标包最多 3 个**。固定 15 个并发槽，每对版本先后执行并交错顺序；未重新校准并发。所有计时结束后再做独立覆盖审计，全部动作及检查点通过。完整配置与哈希见 [plan.json](../results/round6_block/main_60ms/plan.json)。

Bromberger 两个状态分别发生 64、70 次固定条件 core，16/18 个动作都达到扩张上限后回退。prefix-1 达查询上限的动作由 2 增至 8，prefix-10 由 4 增至 10；增加的求解工作没有带来更快的首个正收益模型。真实快照交付候选的记录分支变化数全部为 0，跨原安全区域能力目前只在合成回归中证实，不能宣称在这些开发状态获得了跨分支性能收益。

为解释唯一改善状态，另用冻结原评估器读取已经保存的模型，拆分新增 bit 与输入种子可覆盖缺口的交集。设 `G(z)` 为模型 z 相对正式 S 新增覆盖的 bit 集，则逐动作核对：`|G(x)| = |G(x)∩G(m)| + |G(x)\G(m)|`。这只是覆盖集合的描述性分解，不是因果识别；两项都属于新增样本的合法收益，未改变计分口径，也未运行新的候选搜索。逐动作数据见 [witnesses.csv](../results/round6_block/attribution/witnesses.csv)。

| Bromberger/prefix-1 | Global | block | block − Global |
|---|---:|---:|---:|
| 平均真实新增 bit | 1681.78 | 5083.00 | +3401.22 |
| 其中：与输入种子新增 bit 集重合 | 1228.67 | 4779.89 | +3551.22 |
| 其中：输入种子新增 bit 集之外 | 453.11 | 303.11 | −150.00 |

这份既有快照的种子是前缀之后尚未正式提交的下一模型，自身相对 S 已有 7878 bit 的潜在收益。block 候选新增覆盖中 **94.04%** 与这份种子缺口集合重合；净改善集中在这种重合，而在种子缺口之外平均少覆盖 150 bit。返回模型均不同于种子，故这些重合不能直接删掉或改计为零；但它说明改善高度依赖这个种子与 S 的组合。prefix-10 的种子潜在收益为 0，此时 block 从 245.67 退到 227 bit。

同时，prefix-1 的 16/18 个最终见证是在放开全部 90 个变量后得到的。此前受限查询会改变增量求解器历史及随后模型选择，这是一种可能解释，当前对照没有进一步因果分离。不能把这些结果概括为“小变量块低成本求解成功”，也不能把模型差异未经验证地称为随机噪声。已确认的是特定状态下的更高真实覆盖、更多查询和更高成本。

SMT_random 两个状态分别出现 23、18 次固定条件 core，部分动作发生受限查询未完成后的回退；所有动作均无及时候选。这说明本预算内没有完成有效生成，不证明目标不可达。convert 两个状态各有 16/18 次因依赖分析上限回退；共同的原始 Reach／精确目标编码成本占主导，平均目标编码约为 55–66 ms，单次不可中断的编码调用可能越过动作预算检查点。双方各 17 个动作实际返回超 60 ms，完整时间都已计入，且没有将任何截止后模型计分。**本实现保证交付检查点的截止口径，但不保证每个非中断库调用在 60 ms 内返回。** 无候选的超预算调用保留为零，不作为一次已完成的无改善搜索或不可达证据。

事前规则要求至少两个案例、两个快照支持预算内收益改善，或在覆盖非劣条件下提供明显的同正收益成本下降。当前只有一个正收益改善状态，六个组合为负，且不存在相同正收益的成本改善证据。因此本轮到此停止：保存独立模块和机制证据，不增加目标包、查询次数或预算，不启动 A/B 集成、短预算筛选或长实验。“跨分支生成能力”和“受限求解是否降低完整成本”仍是不同问题，本轮只证明了前者的合成可行性。

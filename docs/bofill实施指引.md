## 三、新优化主线：改变表示，不强制搜索目标

### 3.1 新增一个等价编译模块

建议新增：

```text
include/lia_choice_compiler.hpp
src/lia_choice_compiler.cpp
```

输出对象至少包括：

```cpp
struct CompiledProblem {
    // 编译后的求解公式。
    // 原变量到保留变量/选择变量的完整恢复表达式。
    // 每一步改写的来源与正确性条件。
    // 编译成本、结构规模和回退原因。
};
```

原始 `Formula` 始终保留，不能用编译后的 AST 替换覆盖观察对象。

必须在代码结构上区分：

```text
original_formula：验证、输出、覆盖统计的唯一依据
compiled_formula：仅用于求解
reconstruction_map：将求解模型恢复成全部原变量
```

### 3.2 优化一：成组二选一的整数选择编码

第一版只处理能可靠识别的情况：

- 选择位于顶层必要合取路径；
- 恰有两个备选；
- 两个备选为同一组原变量的完整常量赋值；
- 两组赋值至少一个坐标不同；
- 本次处理的选择组之间没有未解决的变量重叠。

例如：

$$
(\vec x=\vec a)\lor(\vec x=\vec b)
$$

可以用一个新的整数 \(q\) 表示：

$$
0\le q\le1,
\qquad
\vec x=\vec a+(\vec b-\vec a)q.
$$

生成的新变量必须使用不会与原声明冲突的身份，不能仅凭一个固定字符串假定名称唯一。

在求解公式中替换相应原变量，并保存恢复表达式。其他涉及这些变量的约束必须全部同步替换，不能只改 OR 本身。

原公式中确实存在这种成组选择和连接等式，例如 `xH521/xH522` 同时取4795或0，并通过等式影响后续变量。

### 3.3 必须保守处理的情况

一般 OR 不能当作 XOR。以下情况第一版保留原约束，不强行改写：

```text
两个备选变量集合不同；
备选含不支持的表达式或不等式；
条件生效的嵌套选择；
选择组发生复杂变量重叠；
无法确认完整的赋值语义。
```

完全相同的两个备选应合并，不引入一个无意义的自由选择变量。

对重叠组，第一版可以按稳定的 AST 顺序选择互不重叠的一部分进行转换，其余约束在完成已有替换后原样保留。不能为了方便删除剩余组，也不能保留两个相互不一致的恢复定义。

**不要为新选择变量指定当前模型相反值，也不要加入“必须切换某组”的约束。** 这一轮保留全部合法选择，检验表示本身是否更适合求解。

## 四、优化二：可完整恢复的整数等式消元

### 4.1 只消去唯一决定的原变量

从全局必要的仿射等式中，寻找系数为 \(+1\) 或 \(-1\) 的变量，进行精确代入。

例如：

$$
x+y+2z=7
$$

可恢复为：

$$
x=7-y-2z.
$$

所有系数使用 GMP 精确整数，不能用浮点消元或四舍五入。

第一版不使用带除法的整数恢复。例如：

$$
2x+y=7
$$

不能直接把 \(x\) 恢复成截断除法 \((7-y)/2\)。可以选择消去单位系数的 \(y\)，或保留等式。

不能从当前模型选中的分支提取“全局等式”，也不能用历史模型碰巧满足的关系进行消元。

### 4.2 避免消元造成表达式膨胀

这两个实例存在连续关系链。消去全部中间变量不一定更快，可能把稀疏约束展开成大表达式。

因此，使用统一、确定性的成本规则，优先消去：

```text
恢复表达式较短；
引用次数较少；
预计不会明显增加约束系数数量的变量。
```

保留高引用、消去后会造成明显展开的中间量。

为编译设置固定保护，例如总预处理最多5秒，并设置 DAG 节点增长、系数位数和操作次数上限；所有成本计入900秒预算。具体上限在性能运行前冻结，不能看两个实例的结果后分别定制。

达到上限时，保留已经完成且有完整恢复依据的安全步骤，停止进一步变换；若无法保证状态完整，则回退到原公式。不得返回一个只改写了一半的公式。

### 4.3 不直接把通用求解预处理当作采样等价证明

Z3 的 `solve-eqs` 已支持单位系数整数等式等处理，但一般“保持可满足性”的预处理，不自动等于“保留全部原始模型并可逐一恢复”。[Microsoft GitHub](https://microsoft.github.io/z3guide/docs/strategies/summary/?utm_source=chatgpt.com)

本模块只采用有明确双向模型对应的改写。不要简单调用一串 tactic 后，只验证恢复出来的一个模型合法，就宣称没有丢失其他可采样模型。

## 五、模型恢复与枚举必须保持正确

### 5.1 写清楚双向保证

令编译后的变量为 \(y\)，恢复映射为 \(R\)，编译公式为 \(F_c\)。实现说明至少论证：

$$
F_c(y)\Rightarrow F(R(y)),
$$

以及：

$$
F(x)\Rightarrow
\exists y\; \bigl(F_c(y)\land R(y)=x\bigr).
$$

第一条保证不会产生非法模型；第二条保证不会因编译遗漏原公式的合法模型。

若进一步使用压缩变量上的模型阻塞，还需要证明对应映射具有所需的唯一性。没有这个保证就使用下一节的原赋值阻塞方式。

这些保证不意味着采样分布不变，不意味着均匀采样，也不保证覆盖更高。编码变化可能改变模型顺序，性能结论必须由实验给出。

### 5.2 恢复后再验证和评分

每次 SAT 后：

```text
读取所有实际求解变量
→ 按恢复依赖逆序恢复全部原变量
→ 验证原公式 F
→ 在原 AST 上计算完整观察
→ 正式去重
→ 及时输出
```

不能对已被消去的原变量直接调用 model completion 后把默认值当作正确恢复结果。

新选择变量、恢复辅助节点、编译器缓存表达式不得进入覆盖分母、输出模型或原变量去重身份。

### 5.3 阻塞完整原模型

默认用下面的形式排除已输出原赋值 \(m\)：

$$
B_m(y)=\bigvee_{v\in V_{\mathrm{original}}}
R_v(y)\ne m_v.
$$

它排除的是原完整模型，而不是某个选择组合。不能只阻塞所有 \(q\) 的模式，否则可能错误跳过同一选择下许多不同且有覆盖价值的整数解。

若已证明保留变量与选择变量构成原模型的唯一编码，可以用更短的等价阻塞，但必须有相应回归和说明。

发现恢复重复时记录原因，不能简单将其算作新的不同样本。

```text
固定样本数：2、5、10、50、100、1000个不同合法样本
```

不必再跑一套“到1000个就停”的实验。前缀必须保持实际输出顺序，不能事后挑最优1000个模型。

## 九、评测与结果解释

### 9.1 保持原指标不变

所有配置都对**原始 SMT 文件及其原始 AST**评测：

```text
原始节点身份
原始短路访问语义
原始整数低64位
原始覆盖分母
原始变量完整赋值
```

编译后的公式不能用来计算覆盖率。辅助变量不能增加样本差异、模型数量或分母。

运行期间使用已有 C++ 覆盖实现；采样结束后，用冻结 HighDiv 评测器进行独立逐模型或完整前缀审计，不能在主计时期间额外运行昂贵外部审计。

### 9.2 主结果表

逐实例、逐种子报告：

| 指标 | 目的 |
|---|---|
| 900秒覆盖率 | 是否提高固定时间覆盖 |
| 前2/5/10/50/100/1000个样本覆盖 | 是否提高样本质量 |
| 到达指定样本数的时间 | 是否更快 |
| 达到若干共同覆盖水平的时间 | 是否更早取得有效覆盖 |
| 不同合法模型数、正增益模型数 | 区分产量与有效产量 |
| 最长零增益段、无增长时间 | 是否改善高原 |
| 编译、求解、恢复、验证成本 | 解释收益来源 |

没达到对应样本数就写未完成，不能用较短前缀冒充同数量结果。共同完成的比较要同时报告配对数量，不能隐藏困难运行。

历史模型可用于离线说明某个高原仍有已知可达缺口，但不能向在线算法提供这些模型。

### 9.3 必须区分三种结论

**只提高样本产量，覆盖不变：** 说明求解更快，但尚未实现覆盖目标。

**同时间覆盖提高，同样本数不提高：** 说明主要收益来自吞吐，不宣称“又快又好”已经全部达成。

**两者都提高：** 是当前两个目标实例上的正面证据，但三个种子、两个公式不足以证明整个 bofill 类或所有 LIA 上普遍有效。

即使结果不好，也完整报告900秒结果，不临时更换更容易的两个文件，不挑最优 seed，不继续追加参数组合直到获胜。

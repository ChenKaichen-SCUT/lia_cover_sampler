# 第五轮：同预算准备复用验证（测量前冻结）

本协议在机制实验前写入，从 `89e71b83adec3bdd065f7a00ef9d629cdf95c439` 新建 `round5-decomposition-preparation-reuse` 分支。范围只有已有第四轮证据分解和固定开发快照上的准备复用验证。没有 HighDiv 重跑、并发校准、覆盖口径或观察保留条件修改，没有新的 120／300／900 **秒**端到端运行。准备复用默认关闭，不接入在线精修默认配置。

## 固定输入与比较对象

使用 `results/round3_snapshots/states/manifest.json` 中全部 12 份已有 development 快照，不增加或重新采样状态。三例各有 prefix 1、5、10、50，模型、正式前缀、覆盖状态、去重集合及原公式按现有哈希核验。

- Bromberger：已有结果能产生合法候选和少量精修收益的状态。
- convert：已有诊断指出区域、方向与可行性准备昂贵、短步骤预算受限的状态。
- SMT_random：包含已在第四轮独立证明当前 safe 区域零维的 prefix 1 负对照。该结论只适用于固定局部区域，不等于原公式无解或全局覆盖饱和。

旧版和复用版在同一 Release 可执行文件内选路，编译、统计和验证包装相同。旧版保留 `89e71b8` 的决策路径及短步骤时间切分；用同一探针链接保存的原始静态库，先通过充足预算下的模型／增益／候选数／移动数／步骤数回归。原始静态库只用于回归，不与带统计的新版直接做速度比较。

复用版在同一个内部模型上保留一次 `generate()` 栈中的区域、消元、方向构造进度、可行区间和目标游标，分批消费候选。接受内部移动后退出该栈，再以新基点重建全部依赖状态。方向生成策略、原公式验证、观察保留和输出去重保持原样。预算中断不记成已完成的 flat 搜索；中断消耗仍计费，不重启同基点无限尝试。

双方上限相同：6 个步骤／批次、每批 4 个候选、总计 24 个候选，每批最多 256 次目标尝试，整体最多 `6×256=1536` 次尝试。原有连续 2 个无改善完成批次的停止条件保留。准备复用路径不按剩余步骤机械切分准备时间。有限方向、候选和尝试上限仍可导致提前终止，单独报告。

## 主实验与时间口径

主比较为 **双方相同的 60 ms**。12 快照 × RNG seed 0／1／2 × 3 次成对重复 × 2 版本，共 216 次调用、108 对。一个工作槽顺序执行一对，顺序由 `(快照序号+seed+重复号)%2` 预先决定，轮换 old→reuse 和 reuse→old。固定最多 15 个工作槽，沿用用户最近指定的并发上限，不进行并发校准；每个子进程的 OMP／BLAS 线程数限制为 1。全部计时调用结束后才启动独立 Python 覆盖审计，避免审计与计时竞争。

每次调用均为冷快照恢复。计时从 `Formula` 构造前开始，包括公式初始化、读取与逐模型验证前缀、恢复覆盖与去重集合、输入模型评分、搜索初始化、区域／消元／方向／可行性准备、目标求解、候选构造／评分、观察保留检查，以及最终原公式验证和覆盖核验。不得把任何初始化作为不计费的预热。此口径不等同在线采样中公式长期驻留的单次调用，结论只针对本协议。

`full_seconds` 截止于最终验证之后。只有最终验证也在预算内完成，候选才可计入实际额外收益；否则回退已验证的输入模型，晚到的潜在收益另列为 `late_extra_coverage`。非可中断操作造成的超时按实测全额记录，不截断成 60 ms。证据 JSON 序列化与对象析构不在算法时钟中；另报完整子进程墙钟及每 PID 的 `wait4` CPU 时间，提供包含它们的效率值。

## 指标、独立审计与归因

所有调用保留，包括零候选、初始化就耗尽预算和没有覆盖收益的调用。额外覆盖必须减去相同输入模型已有收益：`实际输出对前缀的新 bit − 输入模型对前缀的新 bit`，不得使用输入模型本身的新增覆盖充当精修收益。

逐调用记录初始化、快照恢复、准备各阶段耗时、重复区域准备次数、复用批次数、首次原公式合法候选时间、有效候选数、观察保留通过／拒绝数、内部移动、尝试次数／限制、实际额外覆盖、晚到收益、额外覆盖／完整算法耗时及额外覆盖／子进程墙钟。区域、等式消元、方向、目标池、可行性和基点评估为互斥准备计时，不再叠加包含这些阶段的父计时器。无合法候选的首次时间保留为缺失值，不填 0；条件延迟与有候选调用比例同时报告。

每次实际输出与提议输出均用冻结的原覆盖评测模块独立计算，并验证原公式、观察保留、去重、输入覆盖扣除及截止回退。只加载 HighDiv 评测代码，不启动 HighDiv 采样。计划、原始 JSON、逐调用 CPU／墙钟、审计、CSV、源文件与输入哈希一并保留。

配对差首先对每个“快照×seed”的三次重复取平均，共 36 个簇；不将三次重复冒充独立状态。描述性收益稳定条件预先固定为：36 簇平均额外覆盖差大于 0，中位数不小于 0，至少 2/3 簇非负，至少两个案例和两个快照有正收益，且全部调用审计通过。该规则不是统计显著性检验，不建立向未测试案例推广的结论。必须同时报告逐状态表现、负差和完全无收益的状态，不能只报告总体通过与否。

## 有条件的较长预算诊断与停止条件

仅当主实验中超过一半“快照×seed”簇的双方均至少 2/3 次在初始化后已耗尽预算，或至少一半簇的双方均至少 2/3 次因准备预算退出且尚无合法候选，才考虑一次单独的较长预算诊断。它只包含三例已有 prefix 1，seed 0／1／2，每种 3 次重复，共 54 次调用，双方均 **300 ms**。这不是 300 秒实验，不能将新版 300 ms 对照旧版 60 ms。若执行，触发证据须先保存，再启动；报告与 60 ms 分开。runner 不自动启动该诊断。

如没有稳定的同预算实际额外覆盖收益，就停止扩大实验。保留实现与负结果，不增加 safe 调用或调节时间片继续搜索。局部区域锁死、需要跨分支生成作为独立未解决研究问题保留，本轮不实现跨分支机制。即使出现特定状态收益，也不自动授权完整端到端筛选。

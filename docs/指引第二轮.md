# LIA Cover Sampler 第二轮实现修正与算法增强指引

## 0. 修改基点、目标与不变项

以仓库 `ChenKaichen-SCUT/lia_cover_sampler` 的冻结提交为审计基点：

```text
45faca0f71c83de53c92ed82b4fe9fa2e96676e6
```

在新分支或独立 worktree 中修改。若工作目录已经包含后续提交，先检查差异，不覆盖已有工作，并记录本轮实际基点。

本轮目标是：

> 修复探索和调度中的控制问题，使局部模块能够跨越必要的分支选择，并在输出前将更多覆盖收益集中到同一个合法模型中，减少无效目标求解和低收益阻塞探索。

保留现有 GMP 精确算术、原始模型验证、覆盖差分测试、完整类型输出和全局/探索求解器隔离。不改变原始公式、原始 AST 观察集合、覆盖分母及短路访问语义。

**不得通过删除难例、减少验证、修改指标、把内部候选当正式样本，或者只报告最佳种子来制造提升。** 不自动重跑 HighDiv，不覆盖现有冻结基线和原始结果。新增实验全部使用新目录。

## 1. 修复 A：探索必须拥有独立的超时、重试和退避状态

### 1.1 现有问题位置

检查：

```text
include/core.hpp
    class Global
    unsigned timeout_ms = 50, pack_size = 4;

src/global.cpp
    Global::query()
    Global::explore()
```

当前 `query()` 和 `explore()` 共用 `timeout_ms`。只有 `query()` 遇到未知结果时增加预算；`explore()` 自己遇到未知结果时仅返回，不调整预算。因此，目标求解很容易判 UNSAT 时，困难的探索可能一直重复使用短超时。 

### 1.2 修改要求

将预算状态拆分为至少两份：

```cpp
struct SolveBudgetState {
    unsigned requested_timeout_ms;
    unsigned consecutive_timeouts;
    unsigned consecutive_unknowns;
    unsigned consecutive_fast_successes;
    double cumulative_seconds;
    double cooldown_until;
};

SolveBudgetState target_budget;
SolveBudgetState exploration_budget;
```

首次模型求解继续维护独立状态，不能与这两个状态混用。

探索的超时应根据**探索自己的调用结果**调整。例如可以从：

```text
50 → 100 → 200 → 400 → 800 → 1600 → 配置上限
```

逐步增长。实际调用预算必须同时受以下条件限制：

```text
本模块请求的预算
本次调度动作获分配的预算
整个实例的剩余预算
```

**不能出现“探索请求已经增长到 1600 ms，但调度器永远只分给它 50 ms”的假修复。**

连续快速 SAT 后可以缓慢降低预算，但不要每次 SAT 都立即重置到初始值。不同实例不预先按文件名或首次求解时间分类。

### 1.3 区分返回状态

扩展 `GlobalResult`，使用明确的状态枚举，同时保存求解器原始原因：

```cpp
enum class SolveStatus {
    Sat,
    Unsat,
    Timeout,
    Cancelled,
    ResourceExhausted,
    Unknown,
    NoTarget,
    BudgetExhausted
};
```

外部用户中断、整体截止时间耗尽，不应继续重试。资源限制耗尽也不能仅通过增加 timeout 假装解决。

不要只根据 `reason_unknown()` 中某个字符串判断全部情况；同时记录实际设置的 timeout、实际耗时、外部中断标志和资源设置。无法可靠细分时保留 `Unknown` 和原始原因，不能改记为 UNSAT。

### 1.4 修复重试过程中的阻塞约束累积

当前 `explore()` 每次调用都先添加当前模型的阻塞子句，包括重复尝试同一个模型的情况。

增加当前探索上下文中的 `blocked_model_keys`。同一模型只添加一次阻塞约束。探索返回的新模型经过验证后，也要登记，避免后续仅因 `current` 被其他模块替换，就反复返回已经生成过的探索模型。

允许在阻塞约束过多、连续失败或近期收益很低时重建探索求解器，但必须遵守：

- 重建成本计入探索成本。
- 正式输出的全局去重集合不清空。
- 丢弃旧阻塞约束后，允许重新遇到旧模型，但不能重新输出为新样本。
- 探索上下文的 UNSAT 不进入全局目标冲突缓存。
- 不能把局部探索上下文耗尽直接解释成原公式 UNSAT 或已达到最大覆盖。

不要把“每次超时都立即重建”作为默认策略，否则可能不断丢掉已经获得的求解信息。

### 1.5 必须通过的回归测试

使用可注入的模拟求解器测试预算控制，不依赖机器速度制造超时：

```text
目标求解连续返回 UNSAT。
探索在预算低于 200 ms 时返回 Timeout，达到 200 ms 后返回 SAT。
```

验收：探索预算能够独立增长并取得模型；目标预算不随之改变；重复探索同一个模型不会重复增加相同阻塞约束。

## 2. 修复 B：所有来源的正式覆盖增益必须统一更新 progress

### 2.1 现有问题位置

检查 `src/main.cpp` 中：

```cpp
if (e.model) {
    current = *e.model;
    accept(current, "exploration");
}
```

以及后面的：

```cpp
stalled = progress ? 0 : stalled + 1;
```

探索输出没有更新 `progress`，即使它实际增加了覆盖，停滞状态也可能继续增长。局部和全局目标路径的处理方式还不完全一致。

### 2.2 修改要求

将 `accept()` 从仅返回 `bool` 改为返回正式提交结果：

```cpp
struct AcceptResult {
    bool emitted = false;
    uint64_t new_coverage = 0;
    uint64_t new_observations = 0;
};
```

`new_coverage` 必须是本次模型真正写入正式输出、并更新正式覆盖状态时的增益。重复模型、被拒绝候选、超预算未提交模型，返回的正式增益必须为零。

所有来源统一调用同一个提交接口：

```cpp
auto ar = accept(candidate, provenance);

round_new_coverage += ar.new_coverage;
round_new_observations += ar.new_observations;
```

轮末统一计算：

```cpp
progress = round_new_coverage > 0;
stalled = progress ? 0 : stalled + 1;
```

不能在后一个模块失败时，把前一个模块已经取得的 `progress=true` 覆盖成 `false`。后续改为动作调度后，使用相同原则维护动作级与全局停滞状态。

分别维护“覆盖进展”和“搜索进展”。新种子、新区域或新观察状态可以影响探索策略，但不能冒充新增覆盖。

### 2.3 回归测试

构造已有模型与探索模型，使探索模型翻转一个已观察 bit。必须检查：

```text
第一次输出：new_coverage > 0，覆盖停滞计数清零。
重复提交：emitted=false，不增加覆盖，不虚构进展。
一轮内先取得覆盖、随后另一动作失败：本轮仍然有进展。
```

## 3. 修复 C：用统一的实际成本与收益调度模块

### 3.1 现有问题位置

检查 `src/main.cpp` 中的：

```cpp
round % 5
round % 3
stalled
recent_local_gain
recent_local_cost
```

当前规则主要控制局部模块，随后通过固定的 `if` 顺序进入全局目标与探索。它没有对三个模块统一比较近期收益与成本。

### 3.2 将模块执行改成显式动作

建议增加独立调度模块，把动作区分为：

```text
LocalSafe：当前安全区域内生成
LocalLine：跨分支的一维可行集合生成
TargetSolve：增量覆盖目标求解
Explore：阻塞或重启探索
```

每次只调度一个有明确预算的动作。动作不能在内部悄悄无上限调用另一个昂贵模块。

统一返回：

```cpp
struct ActionResult {
    ActionKind kind;
    double elapsed_seconds;
    uint64_t emitted_new_coverage;
    uint64_t emitted_new_observations;
    uint64_t emitted_samples;
    uint64_t generated_candidates;
    uint64_t unique_valid_candidates;
    ActionStatus status;
};
```

### 3.3 成本必须完整

一个动作的成本包括它引起的目标准备、区域或方向分析、求解、候选生成、评分、必要验证和输出。

同时保留细分阶段计时，但不能将父动作和子阶段重复相加。失败、超时、无目标、重复模型、零收益结果同样进入统计，不能只统计成功动作。

维护近期窗口或指数平滑后的两个指标：

$$
R_a=
\frac{\text{模块近期正式新增覆盖}}
{\text{模块近期完整成本}},
$$

$$
Q_a=
\frac{\text{模块近期正式新增覆盖}}
{\text{模块近期正式输出数量}}.
$$

其中 $R_a$ 用于时间效率调度，$Q_a$ 用于判断是否值得进行输出前改进。没有输出的模块，其样本质量不能被设为无穷大。

实现时应先平滑收益总量和成本总量，再求比值；不要平均大量极短调用的瞬时比值。

### 3.4 保留受控探索，避免永久饿死

利用阶段优先选择近期有效的模块，同时预留少量预算给尚未充分尝试或冷却后需要重试的模块。

探索额度应按**实际耗时**约束，而不是“每五次调用允许一次”：一个耗时两秒的动作不能与一个耗时一毫秒的动作视为同等投入。

在连续低收益或失败后，模块进入有期限的冷却状态，而不是永久禁用。新种子或新覆盖阶段到来后允许重新评估。所有模块都暂时低收益时，使用受限的探索策略，不得据此宣称覆盖已经最优。

调度器只读取实例结构和运行反馈，不读取实例文件名、开发/评测标签或基线结果。

### 3.5 验收

用模拟动作测试：一个模块便宜但持续零收益，另一个较贵但持续产生覆盖。调度器应减少前者的实际时间份额；当收益模式改变后，应能重新分配预算。

这只能验证调度逻辑，不是整体性能证明。

## 4. 区分结构等式和分支等式，保留旧安全区域作为快速路径

### 4.1 现有问题位置

检查：

```text
src/local.cpp
    Region::require()
    Region::kernel()
    Region::interval()
```

当前 `require()` 在析取中选择当前满足的分支，然后把其中的等式加入同一个 `eq` 集合。`kernel()` 随后要求方向保持这个集合中的全部等式。

这对保持当前安全区域是正确的，但可能把可切换分支也固定住。 

### 4.2 不直接删除原有约束，增加等式作用域

建立两类等式系统：

$$
E_Gx=e_G:
\text{已经确认是原公式全局必要条件的仿射等式},
$$

$$
E_Px=e_P:
\text{当前安全区域中需要保持的全部仿射等式}.
$$

第一版的全局必要等式收集采用保守规则：只收集沿顶层合取路径必然成立、且无需依赖分支取值就能转为仿射形式的整数等式。

不能把以下内容直接归入 $E_G$：

```text
某个析取分支中的等式；
蕴含后件中尚未证明前件恒真的等式；
固定 ite 当前分支后才得到的仿射等式；
仅因为多个历史模型碰巧满足而猜测成立的等式。
```

特别注意：

```smt
(= y (ite b x (- x)))
```

虽然等式位于顶层，当前模型下展开出的某一条仿射关系也不自动是全局关系。

允许以后通过独立的 `F ∧ ¬e` 不可满足检查增加全局等式，但检查成本必须计入；超时不能当成证明。

### 4.3 两种方向不能混用验证规则

安全区域方向要求：

$$
E_Pd=0.
$$

跨分支方向只要求：

$$
E_Gd=0,
$$

但必须另外计算完整原公式沿该方向的合法参数。

**禁止删掉分支等式后，继续使用原 `Region::interval()` 并声称区间内所有点合法。** 原函数只基于当前区域的合取条件工作，不能充当跨分支的完整可行性计算器。

为方向记录 `scope`、等式系统签名和来源。矩阵缓存可以按等式系数结构复用；依赖当前模型的区间、截距、分支条件不能错误复用。

### 4.4 增加诊断

记录结构等式数、局部附加等式数、整数变量数、已计算的秩、自由维数和方向构造结果。

若精确秩计算因预算中断，记录 `rank_unknown` 或已知信息，不填一个猜测值。区分：

```text
等式系统确实无非零方向；
方向构造预算耗尽；
生成器没有找到有用方向；
存在方向，但其他约束只允许当前点。
```

## 5. 增加跨分支的一维可行集合，而不是只保留一个区间

这是本轮主要的算法增强，应独立实现、独立开关控制。

### 5.1 定义与接口

固定当前 Boolean 赋值，对整数变量使用：

$$
x(z)=m+zd,\qquad z\in\mathbb Z.
$$

计算：

$$
Z_F(m,d)=\{z\in\mathbb Z:F(m+zd)\}.
$$

新增 `LineDomain`，用经过规范化的、不交整数闭区间之并表示结果。支持无界端点和单点区间，不使用大整数哨兵伪装无穷。

结果至少区分：

```text
Exact
Unsupported
BudgetExceeded
```

只有 `Exact` 才表示已经精确计算整条方向的可行集合。未完成分析不能作为不可达证明。

### 5.2 首版支持范围

先支持：

> Boolean 组合中的算术原子均为全局仿射整数比较；Boolean 变量沿当前方向固定。

对算术原子代入后，得到一元整数比较。例如：

$$
\alpha z+\beta\le0,
\qquad
\alpha z+\beta=0.
$$

等式在 $\alpha\ne0$ 时必须检查整除性；不整除就是空集。严格不等式、负系数和等式否定都必须精确处理。

在原公式 DAG 上进行集合运算：

```text
and：交集
or：并集
not：相对于整个整数域的补集
其他支持的 Boolean 运算：按其精确语义组合
```

不要展开完整 DNF，不要枚举端点之间的整数，也不要把不连通的集合取凸包。

### 5.3 最小验收例

使用：

$$
F=(x+y=10)\land(x=0\lor x=10),
$$

$$
m=(0,10),\qquad d=(1,-1).
$$

必须得到：

$$
Z_F(m,d)=\{0,10\}.
$$

必须能够直接从 $(0,10)$ 跳到 $(10,0)$。使用 $x$ 的第 1 位或第 3 位作为目标，不能误用在这两个取值下都为零的第 0 位。

同时确认旧安全区域路径仍只允许当前分支；两种结果都应有正确的作用域标识。

### 5.4 与覆盖目标及模命中的结合

对于观察节点 $e$，需要时进一步计算：

$$
Z_e=Z_F(m,d)\cap
\{z:\operatorname{Reach}_e(m+zd)\}.
$$

在 $Z_e$ 的各个不交区间上调用已有模命中子程序，再合并计数和选择见证。

**先计算合法且可观察的集合，再使用 bit 周期缩减无界部分。** 不能先在当前点附近截取一个周期，然后断言远处没有其他合法分支。

每个无界区间可以为单个 bit 选择其中一个完整周期窗口；有限区间按实际范围计算。对多个区间的命中计数，要避免重叠重复计数。

排除当前点 $z=0$ 时，先正确分割集合，再进行周期窗口选择。只发现一个已输出见证，不等于这条方向不存在其他不同模型；可进行受限的替代见证搜索，但不得伪称完整枚举。

### 5.5 不支持情况与预算

对于算术 `ite`，首版可以明确回退到旧安全区域或全局求解。以后要支持跨分支 `ite`，应实现分段仿射表示，不能使用当前分支的仿射表达式覆盖整条方向。

设置总分析时间、区间数量、DAG 处理量和大整数位数预算。超过预算就返回明确状态并回退，不能为了减少区间数量合并不相邻区间。

所有最终候选仍然验证原公式。数学子程序的正确性不能替代输出验证。

## 6. 重做方向配额和候选预算，避免稀疏方向与前序方向垄断

### 6.1 现有问题位置

`src/local.cpp::directions()` 先加入不参与等式的坐标方向；达到默认容量后，后续等式核方向可能没有名额。默认基础容量是 16，后面只进行少量两方向组合。 

`src/main.cpp` 的“方向外循环、目标内循环”共享 32 个候选额度；前面的方向可能耗尽额度，而且重复候选也会消耗额度。

### 6.2 为不同方向来源预留容量

至少区分：

```text
坐标方向；
涉及等式关联变量的核方向；
覆盖导向的多基向量组合；
经过对应等式系统检查的历史模型差分方向。
```

不要让坐标方向先占满总容量。可以使用分组配额，某一组不足时再将额度转给其他组。

构造较大支持范围的方向时，可以选择多个自由坐标的变化量，再通过精确回代得到相关变量的变化量。不能仅对已经被截断为 16 个方向的小集合不断做两两随机组合。

多变量方向不以“非零坐标越多越好”为唯一标准。应同时考虑它影响的未覆盖观察节点、系数大小、可行集合是否含非零参数，以及近期实际收益。

方向归一化后仍需检查对应作用域中的完整等式系统。跨分支历史差分不应被旧局部 `E_P` 错误拒绝，而应检查它所声明使用的 `E_G`。

### 6.3 候选分配改为分轮考察

不要让一个方向连续生成大量候选后才轮到下一个方向。改为：

```text
第一轮：每个选中方向至多生成一个有效候选；
第二轮：仍有预算时，每个方向再获得一个机会；
后续：根据已观察收益继续分配。
```

同时区分：

```text
candidate_attempts：构造尝试数；
unique_candidates_scored：实际完成评分的不同候选数；
duplicate_candidates：批内或正式输出重复数。
```

重复候选不占用“不同候选评分额度”，但仍消耗实际时间和尝试额度。这样既避免浪费评分名额，也避免去重后出现无限重试。

在内层循环同样检查动作截止时间，不只在方向外循环检查。

## 7. 让目标与方向匹配，而不是先随机抽 bit 再尝试改变

### 7.1 现有问题位置

`src/core.cpp::active_targets()` 当前主要随机抽节点和 bit。它没有读取方向响应、可行区间或目标历史结果。注释中提到轮转扫描，但函数实际只有随机探测。

### 7.2 建立目标管理器

将目标生成与目标状态维护从简单随机函数中分离，至少记录：

```text
目标身份：节点、bit、目标值、观察条件、公式/指标身份；
覆盖状态；
是否已有合法见证；
是否被全局证明不可达；
历史求解成本、超时次数与冷却状态；
历史顺带覆盖收益。
```

全局不可达信息不能只留在 `Global::query()` 的组包检查中；应在目标进入局部生成和全局组包前就参与过滤。

正式覆盖分母不因目标不可达而缩小。

### 7.3 局部目标选择读取方向影响

建立变量到观察节点的依赖索引。对方向 $d$，优先考虑它可能影响的表达式，并计算：

$$
t_e(m+zd)=\beta_e+\alpha_e z.
$$

只有方向和目标存在合理联系时，才调用模命中。

但这里有一个必须正确处理的例外：

> **$\alpha_e=0$ 不代表这个观察目标一定没有价值。**

若表达式数值不变，但节点由“未访问”变为“被访问”，仍可能产生新的观察状态或补齐覆盖。

因此分开处理：

```text
数值变化目标；
Reach 变化目标；
Boolean 表达式真假变化目标。
```

对于数值常量沿方向不变、且常量 bit 与目标值不一致的目标，可以在当前方向排除。若常量 bit 已符合目标，但 Reach 可能改变，应交给观察可达性处理。

跨分支模式下，Boolean 观察节点也可以沿方向改变，不应像当前局部循环那样一律跳过。

### 7.4 有限目标池中的选择

优先考虑预计可达、能够影响更多剩余观察、历史成本较低的目标，同时保留小比例随机或轮转探索。

轮转位置必须真实维护，避免只实现注释。对于尚未访问的节点，要区分“建立第一次观察”和“补齐相反取值”，不把前者当成已经完成 bit 覆盖。

局部不可达只能缓存到相应的基点、方向、可行集合与观察上下文；不能提升成全局不可达。

## 8. 输出前协同改进一个模型，而不是每个小移动都立即输出

### 8.1 现有问题位置

`src/main.cpp` 中，一旦 `best_gain.covered` 或 `best_gain.observed` 非零，就可能立即调用 `accept()`。当前实现没有独立的单模型改进过程。

### 8.2 增加 `polish_candidate()`

对局部、全局目标和探索产生的候选，都允许经过同一个受限改进接口：

```cpp
PolishResult polish_candidate(
    const Assignment& seed,
    const CoverageSnapshot& committed_coverage,
    ActionBudget& budget
);
```

整个改进期间冻结正式样本集合 $S$，始终比较：

$$
g(m)=f(S\cup\{m\})-f(S).
$$

维护 `work` 和 `best`，尝试多次合法移动。先采用不降低单模型覆盖增益的改进策略，收益相同时再比较新观察状态等次级指标。保留最佳完整模型，时间到即返回。

**不能把多个内部模型的观察并集计入最终模型。** 例如内部模型 $m_1$ 覆盖了缺口 A，$m_2$ 覆盖了缺口 B，但最终 $m_2$ 不再覆盖 A，就不能把最终结果记为同时覆盖 A、B。

只有最后输出的那个模型才能更新正式覆盖；中间模型只能进入内部种子库或诊断记录。

### 8.3 必须重新计算依赖当前模型的状态

当前 `Region` 保存对模型与观察的引用，并包含 `affine_cache`、`required` 等状态。

因此，引入连续内部移动后，不能修改 `work` 却继续沿用旧区域的分支选择、仿射展开、截距和可行区间。

首版采用最稳妥的办法：每次接受内部移动后重建相关区域或一维分析上下文。之后再优化缓存，但只有已确认与基点无关的系数或矩阵结构可以复用。

### 8.4 控制改进成本

每次改进同时受移动步数、不同候选数和时间预算限制。后续是否继续改进，应参考近期额外收益与额外成本，而不是每个候选都固定执行很多步。

初始合法模型应及时输出。对后续候选，不得为了追求“单样本完美”长期不输出任何结果。

纯重复或零覆盖收益模型可以保留作内部种子。为满足数量上限而输出填充模型时，明确记录来源和零收益，不能因此重置覆盖停滞状态。

## 9. 全局目标求解要修复目标包，而不是不断随机重抽

### 9.1 现有问题位置

`Global::query()` 按输入顺序组包，SAT 后增加包大小，UNSAT 后减小包大小，下一轮再接收新目标。它没有在同一个预算动作中针对刚得到的 core 修复目标包，也没有保留已知可满足目标包的见证作为改进起点。

### 9.2 单目标不可达与组合冲突分开

若仅在原公式和目标定义下得到单元素 core：

$$
F\land q_i\text{ 不可满足},
$$

则将该完整目标标记为全局不可达。

若 core 包含多个目标，只保存“这些目标不能同时成立”，不能逐个禁用其中的目标。

Reach 是目标的一部分。数值 bit 可实现，但对应节点不可访问，也可能导致完整观察目标不可达；目标身份必须保持一致。

目标超时只产生难度与冷却信息，不产生不可达结论。

### 9.3 在预算内修复目标包

一次动作中维护当前目标包和最近一个 SAT 见证：

```text
构造一个小包；
查询；
若 UNSAT：从返回 core 中移除一个低价值目标，保留其余目标；
若预算允许：重试修复后的包；
若 SAT：保存完整合法模型，再尝试有限的目标扩充；
预算结束：返回期间最好的合法模型。
```

不要求每次求最小 core，也不做完整全局 MaxSMT。额外查询次数和总耗时必须受动作预算限制，不能给每个内部查询重新分配完整预算。

对 `Unknown/Timeout`，可以缩包、延后或者申请更长时间片，但不使用尚未成立的逻辑冲突。

包大小根据成功率、真实覆盖增益与成本调整，不应仅因为 SAT 就机械增大。

### 9.4 避免长期累积无用目标定义

已解决目标不再进入活跃池；已证明不可达目标尽早过滤。记录已注册激活变量数、商变量数、目标定义数和缓存检查成本。

若后来需要重建全局目标求解器，外部缓存应使用稳定的目标身份，重新建立激活文字映射，不能直接沿用已经失效的求解器内部 AST 身份。

原公式级冲突与局部限制、阻塞枚举产生的冲突继续严格隔离。

## 10. 修正贡献归因：生成来源和后续改进来源分开记录

本轮不是为了把 `convert` 的已有优势重新包装成局部模命中优势。原结果中，该例局部输出直接贡献 174 个新增 bit，全局目标输出贡献 28,065 个，探索输出贡献 22,828 个。该统计说明直接输出来源，但本身也不是完整的因果消融。

引入 `polish_candidate()` 后，不能把“全局求解得到种子，局部稍作改进”的全部收益都归给局部模块。

每个输出记录：

```text
seed_origin
parent_seed_id
refinement_modules
gain_before_refinement
gain_after_refinement
refinement_seconds
final_emitted_gain
```

对同一个冻结覆盖快照，记录改进前后真实的新增覆盖集合。允许报告：

```text
原候选已有且最终保留的收益；
局部改进新增的收益；
局部改进丢失的原候选收益。
```

正式总新增覆盖只计一次。来源统计与关闭某模块后的消融结果分别报告，不用前者替代后者。

## 11. 回归测试与诊断必须覆盖新机制

新增测试至少包含以下内容。控制策略测试尽量使用模拟时钟和可注入求解结果；数学与语义测试使用真实算术及独立 Oracle。

| 测试 | 验收条件 |
|---|---|
| 独立探索预算 | 目标求解持续 UNSAT 不阻止探索预算增长 |
| 重复探索重试 | 同一模型不会反复添加同一阻塞子句 |
| 进展反馈 | 探索新增覆盖能够重置停滞；重复输出不能 |
| 跨模块调度 | 读取所有模块的真实成本，失败调用也计入 |
| 冷却与重新探索 | 低收益模块减少投入，但不会永久失去机会 |
| 等式作用域 | 析取分支等式与当前 `ite` 展开关系不被错误提升为全局 |
| 跨分支可行集合 | 示例精确得到 $\{0,10\}$ 并找到另一分支 |
| 非连续集合 | 不等式否定、等式否定、严格比较和负系数与小范围枚举一致 |
| 无界集合 | 不枚举巨大周期，不因只检查当前点附近而漏掉其他分支 |
| 方向配额 | 大量无关自由变量不能挤掉等式关联方向 |
| 候选公平性 | 一个方向产生很多候选时，其他选中方向仍获得机会 |
| 协同单模型 | 中间模型不更新正式覆盖；最终覆盖与独立评测一致 |
| 缓存失效 | 内部模型改变后，不使用旧分支、旧截距和旧可行区间 |
| Reach 变化 | $\alpha=0$ 但节点可访问性变化的情况被正确处理 |
| 目标冲突 | 三目标冲突不误伤任意两个兼容目标；超时不禁用目标 |
| 贡献归因 | 原种子收益和改进收益不重复计数 |

另增加两个机制测试：

**独立变量协同测试。** 使用若干变量满足 $-1\le x_i\le0$。在提供足够的确定性测试步数后，单模型改进应能构造逐变量相反值的模型，并只输出最终模型。这个测试验证实现能力，不要求默认启发式在所有规模上都达到最优。

**大量自由变量加关联等式测试。** 在许多独立变量之外加入 $u+2v=10$。确认相关方向仍能进入候选，而不是被前面的坐标方向耗尽额度。

### 正式运行保留的轻量统计

按模块保存调用结果分布、总成本、有效候选数、正式输出数和新增覆盖。额外记录：

```text
结构/局部等式秩与分析状态；
非零可行区间数量；
跨分支移动次数；
每类方向的尝试、候选和收益；
单模型改进前后收益；
全局单目标不可达数与多目标冲突数；
探索超时增长、冷却和重建次数。
```

发生错误时保存原公式、模型、方向、区间集合、目标、覆盖快照、查询和配置，能够独立重放。不要通过吞掉异常或跳过失败实例解决问题。

## 12. 分阶段提交与实验验收

### 阶段一：只修复确定的控制问题

实现 A、B，以及相关诊断与回归测试。保持原方向、目标选择和局部生成策略不变，形成独立版本。

这样才能确认后续变化不是仅由修复停滞反馈和探索重试带来的。

### 阶段二：加入跨模块调度

增加独立动作预算和收益/成本比较。保留旧调度开关，用相同代码基础比较。

### 阶段三：改善单样本生成

分别加入方向配额、候选轮转、方向—目标匹配和单模型协同改进。每项使用独立开关，不能只留下一个无法拆解的“大改进版本”。

### 阶段四：增加跨分支方向模式

加入结构等式识别和 `LineDomain`。先通过合成测试与原公式验证，再对真实实例运行。对不支持或分析超预算的情况，保留旧路径与全局回退。

### 阶段五：目标包修复与整体比较

加入目标状态注册、单目标不可达过滤、core 驱动的包修复和预算内扩充。验证其收益是否超过维护成本。

实验先使用现有开发实例与短预算定位问题，再冻结配置评估其余实例。不要按评测案例逐例调参。

至少比较：

```text
原冻结 LIA；
仅修复 A/B；
A/B + 新调度；
加入方向配额与目标匹配；
加入单模型协同改进；
加入跨分支可行集合；
完整版本；
完整版本的关键模块关闭版本。
```

现有 HighDiv 基线继续保留，不自动重新运行。新种子只能与有对应基线的种子进行严格配对；无法配对的结果单独报告。

固定时间实验不能被 1000 个样本上限提前截断；固定数量实验记录前 2、5、10、50、100、1000 个不同合法输出的覆盖和到达时间。未达到某个数量就标记未完成，不补齐、不外推。

**优先检查前 5、10、50 个样本和早期时间覆盖。** 不能只看 900 秒终点，因为后期覆盖平台可能掩盖生成质量差异。

最终报告必须逐项回答：

> 哪个原问题已经被回归测试确认修复？哪个新增机制在真实实例中实际触发？覆盖收益来自哪里？减少了哪些失败或浪费？新增分析成本是多少？哪些实例仍然退化？

若最终仍未同时改善固定时间和固定样本数的覆盖，保留全部数据，明确指出当前瓶颈。**本轮的验收不是“新增模块都能运行”，而是“控制问题确实消失，生成机制确实产生了更有价值的候选，并能用对照实验说明收益和代价”。**

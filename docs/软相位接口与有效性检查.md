# 软相位接口与有效性检查

冻结上游 HighDiv `f2c6e1756b13281d96cbf90a8bd940129e56cce4` 的 Z3 4.14.2；原树 `/tmp/lia-highdiv-frozen` 只读。新树 `dependencies/z3-soft-phase`，性能三配置均链接其 install/lib/libz3.so。可重建补丁和文件哈希位于 dependencies；运行清单另记 ldd 实际路径和二进制哈希。

原 `Z3_solver_set_initial_value` 检查同类型及具体值，经 `user_propagate_initialize_value` 追加强引用到 `m_values`。每次 search 的初始化阶段读取；Boolean 对象先 internalize，再写对应 Boolean 变量的 phase cache，其他类型交理论 initialize_value。它并不限于原变量，但任意表达式是否存在可提示的内部对象取决于 internalization；否定/规范化也不能直接把 AST ID 当 bool_var。提示列表按 trail 作用域保留和累积，并非每次 check 自动替换。没有清空整个提示列表、每查询采用额度和采用事件接口；修改 phase cache 后也不能宣称已经撤回过去影响。因此本轮不用该 API 作为算法。

新增 C API set_soft_phases / clear_soft_phases / get_soft_phase_log，仅 simple SMT solver 支持安装；项目 SoftPhaseBridge 负责所有返回和异常路径的清除。表大小上限 128（目录上限 64）；原表达式及规范化表达式均持有引用。安装使用已有 theory rewriter、消除外层 NOT 并记录符号，不 internalize、不新增断言。规范化同一对象出现多个别名时保守禁用。决策时按正在决策的内部变量对应表达式查表，不缓存跨生命周期 bool_var 身份；未映射明确跳过。日志中的 unmapped 不直接等于“证明已被消去”。

钩子在普通决定变量和原生相位已选出、既有用户决策接口处理之后、assign 之前，只修改局部 is_pos。任何 user propagator 存在即保守跳过。未赋值检查、8 次实际改写、每原子/组一次、64 冲突总额固定；不随重启回溯刷新。原生 guess 仍先执行，其 RNG 调用不增减。达到额度直接原生继续，不启动第二个求解器或追加 assumptions。

每个查询记录提出、映射、遇到、原生相位相同、实际改写、使用过/冲突/额度/特殊接口跳过。最多前 32 个机会事件，再保证保留全部实际改写（最多 8），其余仅累加计数。查表耗时嵌套于 check，报告总成本时不重复计入。最终模型是否满足偏好另由离线审计计算；一个模型的收益不按原子重复归因。

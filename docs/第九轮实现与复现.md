# 第九轮实现与复现

本轮冻结基点 af9b2c6，独立分支 round9-budget-fair-retry。协议见《第九轮实验协议》，离线复核见《第九轮历史失败复核》。旧结果和覆盖语义保持冻结。

## 控制与采样

`interpret_query_exit` 是纯函数，输入原始状态与查询证据；只用 `check()` 自身耗时推断取消是否接近本次实际上限。外部取消与会话截止优先停止；资源耗尽单独分类；疑似局部取消保留 inferred。`grant_query` 对会话与动作剩余预算取较小值，明确记录截短。普通探索只在新入口设置 fixed_levels 后使用 50/200/1000/2000 ms，旧目标查询与微观预算逻辑不变。

每个 `ChoiceAlternative` 有独立 attempt 状态，正式 visits 只在正式提交时增加。公平队列两新一重试；一般 Unknown 最多两次；局部限时失败只在完整获得该级别时晋级。每备选最多六次实际 check、两次截短，最多四个完整限时等级。普通探索的持久求解器达 2000 ms 后仍可在剩余会话预算内继续查询。所有非证明状态均不缓存不可达。

`macro_budget_fixed` 保留 visits/算术范围优先排序；两种宏观配置共同采用当前模型未满足的单备选、每备选预算记录及有限尝试保护。`macro_fair_retry` 再加入新/重试队列和间隔机会。因而两者的配对差异度量队列增量，不能将与旧第八轮的差别完全归因于某一个开关。

`macro_retry_probe` 独立保留新实验流程，B 为连续广泛采样，C 为原微观与新广泛预算管理。两种广泛路径单动作一次查询，动作上限 2.075 秒，内部预留 25 ms 检查点、外部另留 25 ms 正式验证输出；真正耗时仍可能超限，按实际时间排除迟到输出并保留全部成本。C 的广泛份额按初始化后剩余时间 40% 固定总额计费，不再局限于每轮 320 ms；剩余时间继续原微观流程，不休眠。B 不新增求解器重建，C 保留共同的最多两次探索重建。

空目录时不构造宏观求解器，直接调用 plain_broad；目录识别成本计入。宏观队列无可用项时用普通探索。R9 三配置都将 solver random_seed 设为任务 seed（0/1/2），不继承 R8 宏观入口的 xor seed；宏观队列有自己的 RNG，不消费微观/普通模块 RNG。独立 A 点每次从新 Formula/simple solver 开始，种子模型的学习状态不隐含迁移。

## 构建与回放

以下命令从仓库根执行，结果目录必须是新目录。`HIGHDIV_ROOT` 指向原冻结依赖环境；这不是执行 HighDiv 采样。

```bash
export HIGHDIV_ROOT=/tmp/lia-highdiv-frozen
cmake -S . -B build/round9/release -DCMAKE_BUILD_TYPE=Release -DZ3_PREFIX="$HIGHDIV_ROOT/venv"
cmake --build build/round9/release -j6
ctest --test-dir build/round9/release -j3 --output-on-failure

$HIGHDIV_ROOT/venv/bin/python3 scripts/run_round9.py --stage A --binary build/round9/release/macro_diagnostic_probe --output results/round9_diagnostic_queries/main
$HIGHDIV_ROOT/venv/bin/python3 scripts/audit_round9.py results/round9_diagnostic_queries/main --jobs 6
$HIGHDIV_ROOT/venv/bin/python3 scripts/analyze_round9.py results/round9_diagnostic_queries/main

$HIGHDIV_ROOT/venv/bin/python3 scripts/run_round9.py --stage B --binary build/round9/release/macro_retry_probe --output results/round9_mechanism/main_10s
$HIGHDIV_ROOT/venv/bin/python3 scripts/audit_round9.py results/round9_mechanism/main_10s --jobs 6
$HIGHDIV_ROOT/venv/bin/python3 scripts/analyze_round9.py results/round9_mechanism/main_10s
```

A 每批同备选/seed 的四个独立预算点，共 48 次。B 每批两个完整三配置组，共 18 次；批间屏障、同步启动、最多六路。`plan.json` 绑定源代码、二进制、输入、原指标、Z3、协议和审计脚本；`runs.jsonl` 保留 UTC、墙钟/CPU、实际命令及文件哈希。raw.tar.gz 和 archive.json 保留原始查询/候选/时间证据。独立审计在全部采样结束后执行。

只有 B 的 decision.json 为 enter_C=true 才允许：

```bash
$HIGHDIV_ROOT/venv/bin/python3 scripts/run_round9.py --stage C --binary build/round9/release/macro_retry_probe --output results/round9_online/main_30s
$HIGHDIV_ROOT/venv/bin/python3 scripts/audit_round9.py results/round9_online/main_30s --jobs 6
$HIGHDIV_ROOT/venv/bin/python3 scripts/analyze_round9.py results/round9_online/main_30s
```

每份运行记录含可单独重放的完整命令。回放改变输出路径，保留相同公式、前缀、种子、模式和总预算；不同系统负载不保证墙钟轨迹相同。

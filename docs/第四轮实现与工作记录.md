# 第四轮：原因诊断与 A/B 输出精修

基点为第三轮冻结提交 `31cc227`，分支 `round4-diagnostics-ab-polish`。本轮指引保存在 `指引第四轮.md`。旧结果、二进制和数据集保持冻结。

## 诊断实现

普通运行按 batch、direction、target、stage 分开累计次数和成本；direction 终止原因保留混合原因。方向/目标耗时按本身执行阶段计量，不能再把它们与父 batch 时间相加。full trace 仅用于固定快照，保存基点、方向、等式作用域、可行集合和预算退出状态，不使用采样随机数。

`NO_DIRECTION_PROVED` 仅来自已完成的零自由度证明；空生成结果、超时和不支持均分开。`ORIGIN_ONLY` 的结论限定在精确分析的方向及其作用域。safe 模式不把数值命中后未访问节点伪装成 Reach 不可达。重复主原因固定按 base、batch、action、committed 排序，同时保存所有命中标志；一个见证重复不证明其他见证不存在。合法零覆盖候选与没有新模型严格分开。SAME_AS_BASE 在非零整数方向且 z≠0 的正式生成中不可发生，保留分类器单测，不伪造其发生频率。

原先的目标选择、方向排序及 RNG 规则保持；合成测试验证有充分时间、固定操作额度时开关诊断不改变候选和 RNG。记录时钟会带来成本，因此固定快照同时比较关闭诊断、轻量计数和完整 trace，不能把详细 trace 的耗时直接当作普通运行性能。

`scripts/check_diagnostic_witnesses.py` 使用独立 Python/Z3 对作用域内的一元参数查询进行复核，超时仍为 unknown。它不进入正式采样器。`scripts/diagnose_round4.py` 复用第三轮十二个开发快照，另存较大诊断预算的跟进，不覆盖原 60ms 结果。不声称恢复历史每次调用或求解器学习状态。

## 最小组合与状态隔离

完整冻结 A/B 以独立命名空间编译。`scripts/make_ab_adapter.py` 从原 main 生成输出边界适配层，差异保存在 `vendor/frozen_ab/output_adapter.patch`。原生成器先按原规则更新内部状态，再调用正式输出包装器；raw_generator 和 emitted 计数、覆盖及日志明确分开。计数上限只按正式不同输出判断，不能把内部原始模型当作已经交付。

输出精修器使用独立公式、求解上下文和由运行种子/原始序号/固定标签派生的 RNG。只启用 safe polish，6 步、24 个候选、每步最多 4 个，单次最多 60ms。完整观察保留位图检查要求保留原始模型相对正式覆盖尚未见到的每个 0/1 状态；中间模型可以不满足，但最终单独保留最好合格候选。未访问节点不是零值。没有合格候选回退原始模型，重复输出不能填充数量。

首次模型立即交付。累计额外额度为 `0.06 + 0.05 * AB_main_seconds`；冷解析、结构检查、评分、位图检查和替换验证均计入，公共输出日志单独计时。信用不足不等待，临近截止预留输出时间；不可中断超额逐次记账并在后续扣除，不声称硬实时保证或性能最多损失 5%。结构门控只使用当前 Boolean 观察、正式覆盖、已知区域自由度和近期收益，状态变化/周期探测可重新启用；未知结构自由度不被当成无自由度或跨分支可行证明。

debug/trace 模式在每次输出包装前后比较 current、seed_bank、内部覆盖、RNG、停滞反馈、冲突缓存和求解器约束。关闭精修的受控前缀与冻结二进制的模型、类别和决策计数一致。真实时间轨迹仍会受精修墙钟消耗和求解器超时影响，不能声称逐模型一致。

## 验证与已知边界

Release 与 ASan/UBSan 均通过 7 项 C++、18 项 Python 测试。ASan 保持 `detect_leaks=1`，仅沿用第三轮独立复现的冻结 Z3 分配栈 `lp::dioph_eq::imp::imp` 的 LSan 例外；不声称无例外的 leak-clean。详见 `results/round4_dev/builds` 的逐次日志和资源记录。

早期失败记录保留：一次 Python 差分核验传错参数类型，已修正；一次改名测试错误要求限时精修的全部轨迹一致，已改为纯结构门控输入相同，并对两次实际输出分别验证合法性和观察保留。后续联调包括 6 个 2s 队列任务及独立审计、27 次固定快照重放/21 项作用域复核、9 组固定原始前缀变换；这些是框架试跑，不是 120s 性能结果。诊断成本最后补齐无方向证明和 polish 平坦步骤的归属；父步骤与子阶段成本不可相加。

## 正式实验与预设判定

只运行 ab_reference 与 ab_polish；沿用第三轮校准选出的 12 路动态队列，不重做 75 次校准。A 阶段复用 12 个开发快照，3 模块 × 3 种子 × 3 诊断模式共 324 次；B 阶段用已保存 A/B 输出的前 100 个（不足则全部），3 例 × 3 种子；C 阶段为三个开发案例 × 三个种子 × 两配置，共 18 次，每次 120 秒。采样完成后再并行审计，避免正式计时与大量审计争用资源。

运行前冻结条件：120s 平均和配对中位数不退步，至少两个案例均值改善，至少三分之二种子配对不退步；前 10/50 个共同完成前缀均值不退步；观察保留/合法性通过；确实接受过替换；已完成事务的累计额外投入不超过额度加 10ms 计时余量；全部输出事务可核对。不可中断超额即使被记录，也不会自动免除成本门槛。前缀不足 k 必须标为未完成。条件不通过即停止，全部通过也不自动运行 300/900 秒或第三配置。

可复现命令（在仓库根目录，输出目录必须不存在）：

```bash
export HIGHDIV_ROOT=/tmp/lia-highdiv-frozen
/tmp/lia-highdiv-frozen/venv/bin/python3 scripts/round4_workflow.py \
  --configs results/round4_dev/configs.json \
  --prefix-audit results/round4_dev/prefix_audit_final/audit.json \
  --probe build/round4/final/snapshot_probe \
  --replay-binary build/round4/final/ab_replay
```

脚本依次执行诊断、固定前缀变换、120s 采样、原评测器独立审计、raw/formal 状态审计和报告，任一阶段失败保留现场。正式构建哈希见 `results/round4_dev/builds/final.json`；历史阶段一诊断构建作为开发记录保留，不用于最终正式实验。

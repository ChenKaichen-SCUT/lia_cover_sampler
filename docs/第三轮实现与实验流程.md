# 第三轮实现与实验流程

本轮依据 `指引第三轮.md`，从冻结提交 `21befad43206c4917104767138b9317740ecf9ae` 创建 `round3-execution-efficiency`。仅使用 benchmarks 中既定的三个开发案例选择参数，六个评测案例留到候选冻结后的正式实验。HighDiv、第一轮 LIA 和第二轮结果保持冻结。

## 实现及独立开关

- 调度保留近期收益、探测额度和软冷却；全部软冷却时仍选择受限动作。只有确实不可执行的动作受硬限制。已耗尽的阻塞探索上下文等待新的正式输出再重建，避免反复调用同一已耗尽上下文。`--disable work_conserving` 可恢复旧调度。
- `safe` 和 `line` 按方向分析后立即生成候选，之后分轮分配机会；分别限制准备、评分、构造尝试和总时间。后续方向超时保留已有最佳合法模型。`--disable streaming` 恢复批量准备；`--disable directional_targets` 关闭方向相关目标池；原 `--disable fair`、`--disable quotas` 仍独立生效。
- polish 冻结正式覆盖，每步重建依赖当前模型的局部结构，默认总计 6 步、24 个候选、60ms，每步最多 4 个候选。`--polish-step-candidates` 和 `--polish-flat-steps` 可配置，`--disable polish_split` 恢复旧预算分配。共享 SearchOptions 不再被临时改写。
- `--disable rotation_fix` 恢复旧游标行为。空目标包明确记录 `no_target`、预算结束记录 `budget_exhausted`。证明不可达的目标不修改覆盖分母。
- `wall_timing` 为互斥顶层计时；动作内部阶段时间不得再次加入总墙钟。

可用开关的精确拼写以 `build/lia_cover_sampler --help` 和 `src/main.cpp` 为准。LineDomain、GMP 数学核心和原始 AST-bit 指标未改变。

## 正确性与固定状态实验

Release 与 ASan/UBSan 构建均执行 4 项 C++ 和 14 项 Python 测试，记录在 `results/round3_dev/builds/*_verified.log`。冻结 Z3 的大整数退出泄漏已用不链接采样器的独立程序复现；仅排除其 `lp::dioph_eq::imp::imp` 栈，其他 LSan 检查保持开启。诊断、失败记录和说明见 `results/round3_dev/sanitize_diagnostic`。

固定快照来自第二轮已经保存的开发案例轨迹，取前 1、5、10、50 个正式模型组成 S，下一模型作为当前候选 m。保存 F 的哈希、完整赋值、精确 AST 覆盖和来源。并未重建 SMT 学习状态。模块测试在同一状态比较 eager 与 new 的 safe、line、polish，每个状态使用种子 0、1、2；所有返回模型由原评测器独立验证。微基准的增益不等于完整采样轨迹增益。

`snapshot_probe` 是 CMake 生成的独立测试入口；`scripts/snapshot_replay.py --create NEW_DIRECTORY --probe build/snapshot_probe` 从冻结开发数据创建新的不可覆盖快照集。

## 分级流程与晋级规则

`scripts/round3_workflow.py` 在后台依次执行：

1. 在 3、6、9、12、15 并发下各运行同一组 15 个开发任务，每次上限 15s；独立审计后按归一化有效模型吞吐和内存稳定性选择并发。一个任务结束立即补充下一个，每个求解器单线程。
2. 12 个固定快照 × 3 模块 × 3 种子 × 2 版本，共 216 次模块实验，每次模块预算 60ms。
3. screen：A/B 与候选各运行 3 个开发案例 × 3 种子，每次 120s，共 18 次，随后全量独立审计。
4. 通过晋级后才执行 confirm：相同开发案例和种子，每次 300s，共 18 次；再次审计与判定。
5. 再次通过后才执行 final：A/B 与冻结候选各运行九例、seed 0、900s，共 18 次；全量审计和报告。

在运行前固定的晋级条件：终点覆盖平均差不负；至少两个开发案例的种子均值为正；至少 2/3 种子配对不退步；共同完成的前 10、50 个样本覆盖平均差不负；固定状态测试至少两个模块的平均增益/秒差为正；所有新输出审计通过。条件未通过则停止长预算，不根据评测集调参。非法模型、差分不一致等正确性失败直接中止并保存诊断。

## 启动和复核

本机依赖冻结于 `/tmp/lia-highdiv-frozen`；换机器时先按 `dependencies/lock.json` 重建依赖，并更新配置中的本地路径。构建与依赖哈希记录在 `results/round3_dev/builds/final.json`，配置分别为 `configs.json` 与 `micro_configs.json`。

```bash
export HIGHDIV_ROOT=/tmp/lia-highdiv-frozen
/tmp/lia-highdiv-frozen/venv/bin/python3 scripts/round3_workflow.py \
  --configs results/round3_dev/configs.json \
  --micro-configs results/round3_dev/micro_configs.json \
  --snapshots results/round3_snapshots/states/manifest.json \
  --prefix-audit results/round3_dev/prefix_audit_final/audit.json
```

脚本拒绝覆盖已有工作流和输出目录。状态在 `results/round3_dev/workflow.json`，阶段日志在 `results/round3_dev/builds/`。手动运行任一阶段用 `scripts/run_iteration.py --help`；confirm/final 必须提供上一阶段生成的 `--promotion`，并验证配置和证据哈希。

只重新审计、分析或生成报告，不会启动采样器：

```bash
export HIGHDIV_ROOT=/tmp/lia-highdiv-frozen
/tmp/lia-highdiv-frozen/venv/bin/python3 scripts/audit_iteration.py results/round3_screen/main --jobs 15
/tmp/lia-highdiv-frozen/venv/bin/python3 scripts/analyze_iteration.py results/round3_screen/main \
  --micro-analysis results/round3_snapshots/micro/analysis.json
python3 scripts/report_iteration.py
```

审计缓存绑定公式、全部模型、时间戳、指标定义、评测代码、验证二进制、Z3 库和审计报告内容；变化后保留旧报告并重新验证。所有新实验完整审计，不重复验证冻结旧基线。

## 时间与样本数指标

新指引允许在数量上限审计通过后采用一次在线时间轨迹，同时得到时间覆盖与前 k 个样本覆盖。`prefix_audit_final/audit.json` 保存 A/B 和候选代码路径检查、候选受控种子对照；数量上限只影响停止条件和元数据，不分配搜索预算。不宣称独立的实际时间运行一定逐位相同。

统一轨迹取真实前缀，不重排、不挑选最好 k 个。未达到 1000 明确标为未完成。`analysis/curves.csv` 包含前 2/5/10/50/100/1000 个样本与各时间截止点；`paired_by_case_seed.csv` 保存逐案例逐种子配对差；报告短实验时不称其为 900s 性能。

成本记录区分采样 CPU、墙钟、独立审计 CPU/墙钟与微基准交错审计 worker 时间。早期增量编译和诊断没有完整 CPU 计量，不把已计量部分当作完整开发成本。开发期不反复打包 raw；最终证据复核后再归档与推送。

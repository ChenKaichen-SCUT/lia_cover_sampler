# bofill 等价编译与模型恢复

基点 `c758fadb0f3f18b9f3da4a21e0fcdcb29b6e043f`。编译只改变求解表示；原始 Formula、节点顺序、短路观察及覆盖分母不变。规则不读取文件名、历史模型或覆盖缺口。

## 双向模型对应

必要合取中的二选一 `(x=a)∨(x=b)` 指完整常量向量且两向量不同。新整数 q 满足 0≤q≤1，恢复 x=a+(b−a)q。任一编译模型的 q 为 0 或 1，因此满足原选择；任一原模型属于且只属于一个向量，取对应 q 即可提升。其余公式和全部恢复表达式同时替换，所以同时满足所有原约束。相同向量直接代常量。重叠组按原 AST 顺序只转换互不重叠的子集，其余组保留并同步替换。条件 OR、不完整赋值、一般不等式 OR 均不提取。

全局必要等式 `c v + r = 0` 仅当 c=±1 时可消元，恢复 v=−c r；这是整数域上精确且唯一的定义。双向对应来自直接代入等式，完全不用整数除法。当前分支等式不作为全局必要等式。每次消元把定义代入求解式及全部既有恢复式，因此组合后满足 `Fc(y) ⇒ F(R(y))`，且每个 `F(x)` 有满足 `Fc(y) ∧ R(y)=x` 的提升。最终恢复表达式不含已消去的原变量；只允许对最终保留或新增变量补全。

逐次改写的来源子句、表达式及完整恢复映射输出到 structure.json。公式和恢复映射在界限检查后一起提交；中止时保留最后一个完整版本。新增 q 在调用 Z3 fresh API 后还检查其真实 AST 身份不与任何原变量及此前辅助变量碰撞：回归曾发现用户显式声明 `lia_choice!0` 会与 fresh API 产物同名同身份，已修复。线性分析缓存持有其键对应的表达式，防止临时 AST 回收后编号重用。

每个原完整模型 m 使用 `∨v R_v(y) != m_v` 阻塞。因此同一 q 模式下其他不同整数模型仍可枚举，且多个编码若对应同一原赋值也一并排除。没有使用选择模式作为阻塞键。恒真零变量实例有一个空模型，随后正确穷尽。

## 固定成本保护

所有实例共用：最多 5 秒、2,000,000 次计数操作、100,000 DAG 节点，且联合求解和恢复 DAG 不超过原节点数的两倍加 1024；系数最多 4096 位；最多 2048 次单位消元。候选行最多 4 项、变量在联合 DAG 引用最多 8 次、预计项增长最多 8。优先级为恢复宽度、引用数、增长、原变量顺序、子句顺序，不按性能结果修改。GMP 精确计算所有整数。

时间检查是合作式：单次原生 substitute/simplify 调用及退出后的元数据统计不能中断，实际编译时间全部报告并计入外层会话截止；不能将 5 秒说成可抢占的硬时限。统一进程资源限制进一步约束内存。结构保护失败保留已完成步骤，无完整发布就继续用原式。

## 验证与限制

21 项小型回归同时完全枚举原公式及编译公式，比较完整原赋值集合，并对每一个原模型验证提升和往返恢复。涵盖组选择、重叠、条件及一般 OR、链和循环、非单位系数、常量、大整数、Bool、名字冲突、同选择不同整数、空模型及各类预算回退。运行结果见 results/bofill_validation/compiler_regression.log。

这些证明不保证分布不变、均匀性或更高覆盖。没有采用通用 tactic 的可满足性保持作为全模型证明；[Z3 官方策略说明](https://microsoft.github.io/z3guide/docs/strategies/summary/)只作背景。性能只比较新共同持久求解生命周期下的 plain 与 choice_compiled；历史入口另起首次求解器的变化不能归因于编译。

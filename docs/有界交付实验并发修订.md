# 用户明确要求的15线程并发修订

用户在曝光完成、120秒筛选进行中要求“使用15线程并行完成”。此要求覆盖本轮原协议的四路总上限；算法、B/W/K、查询授权、覆盖口径和晋级判据不变。

运行器现采用15逻辑线程资源上限，完整四配置组不拆分，因此允许三个组、12个单线程采样会话并行；有一个完整组结束就补充下一组。机器有16逻辑CPU、8物理核，各组内使用四个不同物理核，跨组可能共享SMT，记录CPU拓扑与实际亲和性。剩余三个名额不构成完整配对组。独立审计使用15个工作进程，仍在所有采样结束后开始。

当次筛选原控制器没有热更新接口。只暂停两个协调进程，采样子进程未暂停、重启或取消；接管程序启动剩余组并使用gate时间戳和GNU time退出收据恢复结果。交接完成时前组已经结束，实际日志计算的采样峰值仍为4，不能宣称本轮已经有15路或12路采样。原始plan和已完成process_result不覆盖；concurrency_amendment.json记录请求上限与实际峰值。恢复的八条进程耗时采用GNU time的0.01秒精度，加共同起点到exec的实测延迟，不使用晚到的监控时间冒充运行时间。

本轮不为展示并行度重跑已完成会话。后续若冻结门槛通过，两个seed的完整验证组可同时启动，共8路900秒会话；未通过则停止。原报告中的四路初始协议保留，通过修订文件和最终报告说明实际执行过程。

调度回归检查三组CPU不重用、组内物理核不同、配对任务矩阵不变以及晋级规则不变；该修改不需要重编译采样二进制。此前Release、ASan/UBSan与完整回归证据继续保存，新增控制器测试另存。

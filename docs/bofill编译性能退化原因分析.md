# bofill 编译性能退化原因分析

本报告基于 `a31e91e` 的只读历史结果，以及新分支的受控消融。历史900秒数据不改写；首次SAT及修复实验的最终数值见另两份报告。

## 已完成的语义核验

两个真实公式各取 `plain_clean` seed0 的前10个正式合法模型，五种模式共100次提升和恢复：原式验证、编译式求值、逐原变量精确往返均通过。`full` 的求解式文本、完整恢复映射、改写顺序与冻结旧输出逐字相同。二元选择变量在具体见证中均为0或1。构造器检查被消元原符号不出现在最终公式与恢复 DAG 中；边界、重叠组、条件 OR、同名辅助变量、大/负整数、Boolean、资源截止的完整有限模型集合测试也通过。这些真实见证检查不构成一般等价性的有限证明。

离线审计首次实现遇到 Python Z3 上下文混用，已改为在原式上下文中解析导出式和恢复表达式，随后完整重验；没有将异常中间结果作为通过证据。结构审计无搜索 API。历史见证未进入任何性能探针。

## 200万操作消耗的解释

详见 `semantic/stage_costs.csv`、`candidate_search_passes.csv`、`rewrite_costs.csv`、`compiler_summary.csv`。原操作限额未改变；计数包含超过上限时触发退出的第2000001次操作，未继续进行改写。

SMT_random 的114个选择组编码已消耗1,888,447次操作，给单位消元阶段留下约11万次；2次单位改写提交后，第三次选中改写在联合 DAG 检查中触顶，事务未提交。最终式仍有95个符合相同规则的可选主元出现位置，并非没有候选。`eq_only` 从原式开始完成50次消元，最终仍有44个可选主元位置。

SMT_real 的85个选择组消耗1,033,088次操作；完整模式完成33次单位消元，在下一次联合 DAG 检查触顶，保留状态仍有86个可选主元位置。单独等式消元完成71次，仍有50个可选主元位置。

这里的“主元位置”指满足规则的变量/必要等式组合，不是不同变量数或必定可连续执行的消元数。离线剩余分析使用最终恢复表达式计入引用次数，并逐条记录行宽、单位系数、原符号、引用和增长拒绝原因。

选择编码前后，global simplify 并未使原必要等式普遍变成不可识别形态：原式与 simplify_only 的剩余候选统计完全一致。选择编码引入了非单位系数项，并改变恢复引用与候选结构；不能把模式间消元数差异全部归因于扫描效率。random/real 原式分别有103/126个合格主元位置，choice_only 分别99/124；其余拒绝类别在逐模式表中保留，不把重复遍历的计数冒充不同候选数。

联合 DAG 扫描消耗了最大的工程操作额度，但 native simplify 的墙钟成本高于 DAG 扫描。该额度本来就没有按 native API 的内部工作量计费；“扫描占大多数操作”不等价于“扫描占大多数运行时间”。重复全式 substitute/simplify 与恢复更新都有实际开销，进一步消元是否有价值必须结合首次求解消融判断。不得以调高额度代替修复。

## 结构解释的边界

`eq_only` 中显式 OR 数保持原式的364/269，没有引入选择变量；choice_only/full 分别移除114/85个被证明安全的必要二元选择组，其余一般或条件 OR 保留。original、simplified、choice_only、eq_only、full SMT-LIB 和完整恢复均独立保存。

辅助选择变量进入算术表达式及其约束共现关系、必要等式连接图和系数大小分布保存在每个模式的 `structural_analysis.json`。这些是结构描述，不是 Z3 内部求解时间的直接解释。SMT-LIB 重解析可改变 AST 共享与根包装，增长限额和精确前后 DAG 应以 C++ 编译器记录为准，不把 Python 重解析节点数差异当成实际编译变化。

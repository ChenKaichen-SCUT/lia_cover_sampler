# 第五轮独立复核：收益是否转化为预算内可交付改善

本附录只读复核已经完成的结果，没有重新运行采样、机制实验或覆盖评测，也没有修改冻结代码及实验脚本。主比较为双方相同的冷启动 60 ms；双方相同的 300 ms 仅用于事前规则触发后的初始化／准备诊断，不能替代主比较。

## 证据及统计核对

复核对象为 [60 ms 产物](../results/round5_preparation/primary_60ms/COMPLETE.json) 和 [300 ms 诊断产物](../results/round5_preparation/diagnostic_300ms/COMPLETE.json)。重新核对了两组 `plan.json`、`runs.jsonl`、`TIMED_COMPLETE.json`、`AUDIT_COMPLETE.json` 与完成标记中的 SHA-256，以及每条调用记录所绑定的完整探针输出 SHA-256，全部匹配。两组原覆盖评测的独立审计均通过。

从 `runs.jsonl` 重新计算配对差，先对同一快照、同一种子的三次重复取均值，得到：

| 比较 | 调用／顺序配对／快照×种子组合 | 正／零／负组合 | reuse − old 的组合平均额外覆盖差 |
|---|---:|---:|---:|
| 主 60 ms | 216／108／36 | 0／33／3 | −6.824074 bit |
| 单独诊断 300 ms | 54／27／9 | 0／7／2 | −0.962963 bit |

这些结果与已生成的汇总一致。没有把三次重复视为三个独立开发状态，也没有删除无候选调用。60 ms 的最大实际尝试数为 328，300 ms 为 101，均未触及双方共同的 1536 次总上限；两组最大评分候选数均为 24。

计分口径检查见 [探针](../src/preparation_probe.cpp)、[运行和独立审计脚本](../scripts/run_preparation_pairs.py)：从 Formula 初始化前开始计时，包含快照恢复、搜索初始化、准备、评分、观察保留和最后原公式核验。实际额外覆盖扣除输入模型已有 gain。最后核验结束超过总预算时，实际交付输入模型，主收益为零，潜在改善单列为迟到收益。`full_seconds` 截止算法最后核验；启动、证据序列化、退出等另计在进程墙钟时间内。

## 60 ms 的下降主要不是迟到造成的

双方各 108 次调用，old 的实际额外覆盖合计为 1032 bit，reuse 为 295 bit，减少 737 bit。平均每调用为 9.555556 → 2.731481 bit。损失可精确定位为以下两部分。

**Bromberger／prefix-10 的种子 0 和 2 合计损失 663 bit，约占总损失的 90%。** 三次重复均出现相同的收益差，不能未经验证地归为计时噪声。

| 状态 | 每次 old → reuse 实际额外 bit | 每次合法候选数 | 每次尝试批次数 | reuse 完整耗时范围 |
|---|---:|---:|---:|---:|
| prefix-10，seed 0 | 120 → 1 | 15 → 2 | 6 → 2 | 28.39–31.26 ms |
| prefix-10，seed 2 | 102 → 0 | 11 → 0 | 6 → 1 | 21.48–32.44 ms |

这是日志直接支持的早退事实：上述 reuse 调用均未达到时间、总尝试或候选数量上限，`preparation_reuse_hits` 为零；它们提前结束，获得的合法且满足观察保留条件的候选更少。prefix-10 的这些候选没有因观察保留条件而被拒绝。因此，此处准备耗时下降不能全部解释为“同样的搜索工作变便宜了”。

源码提供了与这些事实一致的机制解释：[Search::polish_candidate()](../src/search.cpp) 在一次准备流返回且没有接受新内部模型时终止，不在同一基点重新开启一轮；[Search::generate()](../src/stream.cpp) 只继续当前保留的方向状态及目标游标。旧路径在一次未改善后仍可能继续下一短步骤，对同一基点再次构建并消费 RNG，产生另一轮方向／目标。这里的比较包含“保留一次有限流，耗尽后不重启”的停止行为变化，不是候选序列完全相同、只删除重复计算的纯缓存消融。日志不足以为每个未生成的候选指定唯一因果路径，但已足以排除“主要由截止迟到造成”的解释。

**剩余 74 bit 来自 Bromberger／prefix-5、seed 1、repeat 1 的截止差。** 双方潜在额外覆盖都是 74 bit：old 在 56.512079 ms 完成，reuse 在 60.615788 ms 完成。后者按事前规则回退，主收益为零。这里输入 gain 为 7 bit，候选 gain 为 81 bit，计入的差值是 74 bit，并未把已有覆盖重复记为收益。

逐调用证据见 [60 ms 配对表](../results/round5_preparation/primary_60ms/pairs.csv)、[调用表](../results/round5_preparation/primary_60ms/calls.csv)。

## 60 ms 的零结果不能都解释为局部锁死

SMT_random 和 convert 的所有 60 ms 调用都在初始化／快照恢复阶段耗尽预算：双方分别有 72／108 次 `setup_exhausted`，这些调用没有进入 safe 搜索，没有方向准备、目标尝试或本次局部零维证明。因此，这部分结果只说明本次完整冷启动口径下没有预算进入精修，不能作为“执行搜索后证明局部锁死”的新证据。

24／36 个快照×种子组合满足事前冻结的较长预算触发条件，见 [诊断触发记录](../results/round5_preparation/longer_budget_trigger.json)。随后只在三个既有开发案例的 prefix-1 上，对称运行双方 300 ms，共 54 次调用；没有增加其他快照或启动端到端实验。

## 300 ms 诊断区分了三种限制

**SMT_random／prefix-1：减少重复证明，不能创造自由方向。** 双方各九次调用均实际进入搜索并证明当前 safe 区域零维，无合法候选。区域构建总数由 18 降到 9，其中同一基点的重复区域构建数由 9 降到 0；平均完整耗时由约 99.85 降到 90.61 ms，实际额外覆盖仍为零。该结论只针对当前 safe 区域，不能外推为整个公式没有其他模型。

**Bromberger／prefix-1：合法候选未转化为满足观察保留条件的额外覆盖。** 双方各产生 180 个合法候选；其中满足观察保留条件的分别为 old 3 个、reuse 0 个，双方最终额外覆盖均为零。这里可以观察到准备省时，不能声称覆盖收益改善，也不能据此放宽原观察保留条件。

**convert／prefix-1：准备和候选生成改善，但可交付收益没有改善。** 平均准备耗时由约 161.09 降到 127.64 ms；合法且满足观察保留条件的候选总数由 63 增至 166。潜在额外覆盖合计由 177 增至 300 bit，但该数包含迟到结果：old 为 26 bit 及时收益加 151 bit 迟到收益，reuse 的 300 bit 全部迟到。reuse 九次完整耗时均为 309.37–312.80 ms，超过双方共同的 300 ms 截止；实际可交付额外覆盖为 old 26、reuse 0 bit。不能用更多候选或更高迟到潜在收益替代预算内结果。

逐调用证据见 [300 ms 调用表](../results/round5_preparation/diagnostic_300ms/calls.csv) 和 [配对表](../results/round5_preparation/diagnostic_300ms/pairs.csv)。

## 复核结论及解释边界

本次有限流准备复用实现确实减少部分准备工作，但**没有在相同完整预算下稳定增加可接受的覆盖收益**。60 ms 没有任何正收益的快照×种子组合；对称 300 ms 诊断也没有正收益组合。候选数量方面的改善仅出现在特定状态，且尚未转化为截止前通过全部检查的交付收益。

该负结果不等于“任何准备缓存都会降低覆盖”。当前实现的早退行为、观察保留限制和完整截止成本分别约束了不同状态。应在此停止扩大实验，不通过追加 safe 调用、再调时间片或继续放宽预算来修饰结论。对于已经证明当前 safe 区域零维的状态，区域外合法模型是否存在、以及如何跨分支生成，作为独立研究问题保留；本轮没有实现或验证跨分支机制。

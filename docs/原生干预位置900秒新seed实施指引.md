# 下一阶段：冻结干预位置策略，使用新seed进行900秒配对验证

基于 GitHub 仓库 `https://github.com/ChenKaichen-SCUT/lia_cover_sampler` 的分支 `native-position-bounded-delivery`，最新报告提交 `091b6a7`，开展一次新的900秒冻结验证。

## 一、任务目标

本轮不再开发新算法，不修改现有相位选择、随机概率、决策窗口、候选交付、阻塞策略和预算控制。直接验证当前已经实现的两种配置：

- `first_immediate`：原生随机干预，始终选择第一个支持的原生决策对象。
- `position_immediate`：在每次查询前，均匀选择第1–4个支持的原生决策对象，仍然最多干预一次。

两种配置都立即输出合法模型，不启用批次排序、不启用在线反馈学习，也不使用历史HighDiv模型、已知覆盖缺口或离线选出的高价值候选。

算法以冻结实现提交 `75cd6b6` 为准。首先核对当前源码及依赖与该提交的算法哈希一致。允许新增实验调度、独立审计和报告脚本，但不得改变采样决策或性能参数。

本轮必须实际执行900秒验证，不再使用上一轮已经失败的自动晋级条件阻止这次明确要求的新实验。

## 二、实验对象与数量

固定两个bofill实例：

```text
SMT_random_LIA_ex14600_2600_100.smt2
SMT_real_LIA_ex8500_2400_100.smt2
```

固定使用此前实验未使用的新seed：

```text
3、4、5、6、7、8、9
```

因此，总任务数量为：

```text
2个公式
× 7个新seed
× 2个配置
= 28次900秒采样
```

每个“公式＋seed”的两个配置构成一个不可拆分的配对组，共14组。

全部参数、seed、任务顺序、算法二进制哈希和验收指标必须在运行前冻结，不根据前一批的结果修改后一批。

## 三、使用最多15线程，但保持配对公平

本轮明确要求提高CPU利用率，不继续使用“一次只执行4个采样进程”的保守协议。

当前服务器具有8个物理核心、16个逻辑CPU。先通过 `lscpu -e` 和实际CPU affinity核对物理核心与SMT sibling映射，不得假设相邻CPU编号属于同一核心。

正式调度采用：

```text
最多14个单线程采样进程同时运行
1个逻辑CPU用于监督器和调度
其余1个逻辑CPU预留
```

每批同时启动7个完整配对组，即14个采样进程。28个任务分两批，每批14个任务。

允许采样进程使用SMT逻辑线程，但必须尽可能平衡两种配置的资源竞争。建议预留一个完整物理核心供监督器和系统，其余7个物理核心的14个逻辑线程运行采样。通过循环错位分配，使同组两个配置位于不同物理核心，而每个工作物理核心均同时承载一条 `first_immediate` 和一条 `position_immediate` 任务。第二批轮换核心与配置的映射。

这是一项**14路逻辑线程并行实验，不是14个独立物理核心实验**，报告必须准确说明。

任务采用完整组同步释放、批间屏障。组内不能出现一个算法已经运行几十秒、另一个才开始的情况。

在正式开始前核查内存、cgroup限制及上一轮峰值RSS。只有确认14个采样进程的总内存使用具有安全余量才采用14路；若不满足，运行前统一冻结更低的完整配对组并发数，保证两种配置对称，记录原因。不得在看到性能结果后随意调整并发量。

如果实际机器拓扑与报告不一致，也按上述原则重新确定可用并发数，而不是错误声明使用了15个独立核心。

## 四、冻结原始生成机制

两个配置必须保持：

```text
原始SMT公式；
持久增量simple solver；
每次check最多一次相位机会；
KeepNative和FlipOnce概率均为50%；
最多检查前32个原生决策；
首次合法模型之前不干预；
完整模型阻塞；
相同的查询时限等级；
相同的正式输出与覆盖规则。
```

唯一主要区别应当是干预对象的位置选择。

`first_immediate` 固定选择第一个支持对象；`position_immediate` 使用冻结的独立随机数流选择第1–4个支持对象。

若某次查询未达到选定位置，记录真实原因，不临时补给另一个决策位置，也不追加求解。

运行前通过Release、ASan/UBSan及适用回归核验算法身份、合法性、预算、相位生命周期和模型阻塞。

## 五、900秒覆盖曲线

本轮不能只看900秒终点。

每次运行均记录完整模型与实际写完时间，计算：

```text
固定时间：
1、5、10、30、60、120、180、300、450、600、750、900秒

固定样本数：
2、5、10、20、50、100、200、500、1000个不同合法模型
```

样本不足的前缀明确标记 `NA`，不能按已有样本补齐，更不能删除零覆盖增益样本。

分别给出两个算法随时间增长的covered-bit曲线，以及逐seed差值：

$$
D_s(t)=C_{\mathrm{position},s}(t)-C_{\mathrm{first},s}(t).
$$

重点分析：

**早期阶段：** 10、30、60秒是否出现重复退步，退步有多大，主要与首模型到达时间、模型生成间隔还是模型互补性有关。

**中期阶段：** 120、300、600秒位置策略是否开始追上并超过旧版本。

**900秒终点：** 是否在新的seed上保持优势，以及每个seed的增益幅度。

此外，计算0–900秒覆盖曲线下面积（AUC），用于描述整个运行期间的累计覆盖表现，避免只比较一个终点。AUC必须基于实际阶梯覆盖曲线计算，不能用少数检查点粗略求和冒充精确值。

## 六、同样本数的质量比较

两个算法都按照真实生成顺序输出所有及时、不同、合法模型。

逐seed比较相同前缀的累计covered bit，尤其检查前10、前100和前1000个模型。

同时记录达到这些样本数需要的实际时间，防止出现“同样本数更好，但要花更久才能获得这些模型”而没有披露成本的情况。

对前缀差异，分别统计Boolean节点、整数变量和算术表达式的收益，以及整数0–7、8–31、32–63位的贡献。

不将模型变量变化数简单作为覆盖质量指标。

## 七、观察缺口与高原分析

本轮结束后，再使用历史HighDiv合法模型的覆盖集合进行只读诊断。

检查新策略是否补齐了以前native未覆盖、但HighDiv已提供合法见证的bit。同时统计：

```text
新位置策略独有covered bit；
旧位置策略独有covered bit；
两者共同covered bit；
双方模型合并后才能形成的covered bit；
双方都没有得到但HighDiv已证明可达的bit。
```

不能只看旧缺口补齐数量。补齐旧缺口同时丢失更多其他覆盖，仍然可能是整体退步。

HighDiv历史数据不能进入在线采样器，只能在所有实验结束后用于分析。

另分别记录最长无covered增长时间、连续零增益模型段、连续零新观察模型段，以及后期300秒内新增模型数和covered bit。

检查新位置策略是否真正缓解高原，还是仅让早期模型覆盖提前、后期仍然停滞。

## 八、统计与判断规则

本轮的主要评价对象是**每个公式7个新seed的900秒配对结果**，不是把每个查询或每个模型当作独立重复。

预先冻结：

**主要指标：** 900秒终点覆盖差。

**次要指标：** 0–900秒AUC、30/60/120/300/600秒覆盖、共同前10/100/1000样本覆盖、首次正增益时间、高原长度、不同合法模型数量及完整成本。

按公式分别报告均值、中位数、7个逐seed差值、胜平负，不将不同公式的bit数量直接相加。

可将“两个公式各至少5/7 seed在900秒严格胜出，且900秒覆盖差中位数均为正”作为**长期改善的初步判定标准**。同时必须完整披露全部早期时间与样本数退步，不将该标准等同于算法在所有预算下都更好。

若900秒改善但30/60秒或前10样本持续退步，应标记为“长预算收益伴随早期风险”，不能宣称已经全面满足两个目标。

若900秒结果不稳定，或某一个公式持续下降，不能因个别成功seed就晋级。

不根据结果事后改变评判标准，不追加新seed挑选有利结果，不调整K范围或翻转概率。

## 九、与HighDiv的关系

本轮不重新运行HighDiv。

历史HighDiv的900秒覆盖可以在报告中作为背景参考，但其编译、并发和seed条件不同，不能写成本次严格配对结果。

只有新位置策略相对原位置策略的同条件比较，才作为本轮主要性能证据。

若新策略900秒表现稳定，并且确实缩小了HighDiv历史覆盖差距，再单独规划下一轮同条件HighDiv正式比较；本轮不自动启动。

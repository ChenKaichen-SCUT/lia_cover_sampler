
# 下一阶段任务：原式持久增量求解与覆盖导向软相位偏好

## 一、基点、目标与修改边界

基于仓库：

```text
ChenKaichen-SCUT/lia_cover_sampler
```

冻结提交：

```text
07098bc
```

新建分支，例如：

```text
coverage-soft-phase
```

本轮实现并验证：

> 在原始公式和持久增量求解过程中，根据当前尚未获得的 AST 观察，为少量原生 Boolean／理论原子决策提供可被放弃的相位偏好，使求解器更早尝试可能产生互补观察的方向。

这里的“相位”是**一个已经被求解器选作决策的 Boolean 原子，先尝试真还是假**，不是要求某个完整 OR 分支必须成立。

### 必须保持不变的内容

保留原始公式、原始 AST、完整模型阻塞、持久求解生命周期、原模型验证、原覆盖指标及总时间预算。

本轮不得：

- 重新启用投影生成、整数选择编码或强制 OR 分支查询；
- 将偏好写成 `solver.add(...)`、assumptions、MaxSMT 目标或额外约束；
- 为满足偏好额外调用第二个求解器；
- 因偏好没有实现而拒绝一个合法的新模型；
- 同时修改决策变量优先级、重启策略、冲突分析和整数算术算法。

**首版只改变少量普通决策的相位。**

新增独立入口，保留当前 `bofill_sampler` 和历史结果不动。默认模式仍为 `plain`。

### 2.2 先核对初始化提示，但不要依赖未经验证的行为

检查冻结源码中的：

```text

```

回答：


本轮允许并优先采用一个最小的原生相位钩子。现有初始化提示最多作为接口诊断，不作为另一套性能候选反复调参。

### 2.3 最小钩子的介入位置

冻结源码的 `context::decide()` 已经包含：

```text
原生选择决策变量
→ 得到原生相位
→ 处理既有用户决策接口
→ 构造决策 literal
→ 普通 assign
```

新钩子应在**原生决策变量已经确定、真正进行普通决策赋值之前**检查偏好。

严格保留：

```text
原生选择的变量
原生传播
冲突分析
回溯
学习子句
正常模型验证
```

仅在下列条件同时满足时，允许覆盖本次相位：

```text
该对象是当前尚未赋值、可正常决策的原子；
能可靠映射到偏好表中的原表达式；
不是已经被传播强制确定的值；
没有需要优先遵守的其他特殊决策接口；
本次查询的偏好额度尚未耗尽。
```

如用户决策接口已经接管本次选择，首版直接跳过，不覆盖它。

未命中、映射不确定或额度耗尽时，执行原生相位，不额外抽取求解器随机数。

### 2.4 项目侧接口

新增类似下面的接口。以下名称是**拟新增的项目接口**，不是假定 Z3 已有这些 API：

```cpp
struct SoftPhasePreference {

```

偏好表按查询替换，不能无限追加历史提示。异常、取消、返回 SAT／UNSAT／Unknown 后，都必须正确结束本次偏好生命周期。

### 2.5 映射与内存安全

原 AST 节点与内部 `bool_var`／`literal` 的映射可能涉及规范化和否定符号，不能把原 AST 编号直接当成内部变量编号。

要求：

```text
保留表达式引用，避免 AST 回收造成身份复用；
记录 original_atom → internal_literal 的映射及符号；
在内部对象生命周期变化后失效或重建映射；
不存在可靠映射时明确跳过；
不能为了让偏好生效而新增辅助断言或新的选择变量。
```

**“整个备选条件成立”与“某个原子取真”必须分开。** 不能把一个多变量合取条件当成单个原子的含义。

## 三、构造有语义依据的条件观察摘要

### 3.1 首版从可靠的二选一结构开始

可复用已有 `ChoiceCatalog` 的**只读结构识别能力**，但不得调用 `MacroChoiceGenerator` 发起分支查询，也不将目录转换成整数选择变量。

优先处理顶层必要合取路径下的完整常量二选一：

$$
P_0\lor P_1,
$$

其中两个备选给同一组变量赋不同常量向量。

例如：

$$
P_0=(x=0\land y=0),
$$

$$
P_1=(x=4795\land y=4795).
$$

若取原式已经存在的原子：

$$
a\equiv(x=4795),
$$

则在完整公式要求上述选择成立的前提下：

$$
F\land a\Rightarrow P_1,
$$

$$
F\land\neg a\Rightarrow P_0.
$$

因此，可以将这个**已有原子的两种相位**分别关联到两个备选的条件信息。

这必须有明确的结构前提。对于一般 OR、变量集合不同、条件生效的嵌套选择或不能证明上述蕴含的情况，不使用这种推导。

某个坐标在两个备选中取值相同，不能用它作为区分原子。

### 3.2 不修改公式，只计算条件下的确定值

对于一个原子相位 \(l\)，构造有限的条件赋值环境，并在原 AST 上进行有界传播：

```text
由该相位可靠推出的常量赋值；
全局必要等式中，可以精确推出的其他常量；
所有参数均已确定的算术表达式；
能够确定真假和访问条件的 Boolean 节点。
```

必要等式传播首版仅使用容易审计的规则，例如只有一个未知量且该量系数为 ±1。使用精确整数，不能做浮点近似或整数截断除法。

这一步是**分析原公式的后果**，不是消元送入求解器的公式。

不调用 SMT 搜索来证明摘要，不执行全公式最优化。分析不完整时可以少记录观察，但不能猜测。

### 3.3 必须保留原评测器的访问语义

“能算出节点的值”不代表“评测器一定访问这个节点”。

对短路 AND／OR、条件表达式和共享节点，使用与冻结评测器一致的访问规则。首版采用三值式保守判断：

```text
确定访问；
确定不访问；
访问情况未知。
```

只有“确定访问且值确定”的节点，才能进入保证观察摘要。

无法确定访问的节点可以记为诊断信息，但不能进入保证收益分数。不要为了多得到几个分数而错误统计不可见节点。

### 3.4 摘要数据与正确性条件

每个相位保存：

```text
原子身份与真假方向
来源选择组
推导出的原变量值
使用的必要等式
确定访问的节点
确定的 zero/one 观察位图
截断和不支持原因
```

记摘要为 \(G(l)\)。必须满足：

$$
m\models F\land l
\quad\Longrightarrow\quad
G(l)\subseteq O(m),
$$

其中 \(O(m)\) 是原评测器在模型 \(m\) 下实际观察到的“节点、bit、取值”集合。

如果有限推导出现冲突，可以关闭该摘要并记录原因，但不能把它当成未经验证的全局 UNSAT 结论。

### 3.5 分析成本必须有界

首版使用稀疏观察位图及缓存，不建立“所有 bit × 所有变量”的巨大矩阵。

统一设置操作次数、摘要节点数和总准备时间上限。建议总准备上限先固定为1秒，且全部计入会话；达到上限后使用已经完整构造的可靠摘要，其余标记未完成。

不要在每次决策钩子中重新遍历 AST。**热路径只查表；摘要分析在正常模型之间完成。**

参数在正式运行前冻结，不根据两个公式的结果分别修改。

## 四、按实时缺口计算偏好

设当前正式集合已经观察到的0、1分别为 \(V_0(S)\)、\(V_1(S)\)，相位摘要的两部分为 \(G_0(l)\)、\(G_1(l)\)。

定义：

$$
L(l,S)=
\left|G_0(l)\cap\bigl(V_1(S)\setminus V_0(S)\bigr)\right|
+
\left|G_1(l)\cap\bigl(V_0(S)\setminus V_1(S)\bigr)\right|.
$$

它计算的是：**这个相位若在最终合法模型中成立，摘要能够保证补齐多少个当前缺口。**

在摘要正确且使用同一覆盖状态的前提下：

$$
m\models F\land l
\Rightarrow
\Delta(m\mid S)\ge L(l,S).
$$

这不是可满足性保证，也不是求解时间保证。

首版采用如下规则：

```text
分别计算同一原子的真、假两侧分数；
优先 covered 缺口数更高的一侧；
covered 分数相同时，再比较首次观察数；
仍相同时保留原生相位，不为了“介入”而介入。
```

不同原子摘要可能重叠，不能把它们的 \(L\) 直接相加声称整次查询的保证收益。

没有可靠摘要、两侧都没有潜在新观察或映射失败时，使用原生策略。

每次正式提交模型后更新分数。一次 `check()` 内冻结覆盖版本，不能在搜索中修改评分对象。

## 五、“可被放弃”必须在代码中成立

### 5.1 首个模型不干预

首次求解仍按 plain 获取。第一个完整合法模型及时写出后，再开始构建覆盖偏好。

不得为了准备摘要延迟首模型交付。

### 5.2 首版介入额度

使用简单、固定、可审计的额度，例如：

```text
每次 check 最多实际覆盖8次相位；
同一原子、同一选择组每次 check 最多介入一次；
本次 check 的冲突数达到64后停止继续介入；
额度不因内部 restart 或回溯而重新发放。
```

这组值是待验证的统一初始配置，不是最优参数。首轮不要展开参数网格搜索。

达到额度后，只是后续决策回到原生相位，不撤销求解器已经正常获得的学习状态，也不重新启动一次普通查询。

### 5.3 偏好不能变成强制条件

出现以下情况都允许正常发生：

```text
偏好被传播覆盖；
尝试偏好后出现冲突并回溯；
最终模型没有实现偏好；
求解器返回另一个合法模型。
```

这些都不能作为拒绝输出的理由。

尤其不能在“最终模型没听偏好”时，自动追加：

```cpp
solver.add(preferred_atom);
```

也不能再次调用带该偏好的 assumptions 查询。

### 5.4 保留搜索自由，不承诺无代价

本轮能保证的是偏好没有缩小合法解集合；不能保证决策路径不变，也不能保证模型供给绝不下降。

关闭显式偏好，只是停止后续覆盖相位，不代表恢复到了一个“从未被干预过”的求解器状态。报告必须保留这个区别。

## 六、记录实际生效情况，不能只记录“建议过”

新增以下分层计数：

| 层次 | 必须记录 |
|---|---|
| 摘要 | 支持的组、支持的原子、两侧摘要大小、截断数 |
| 映射 | 映射成功、被简化消去、符号转换、不支持 |
| 机会 | 原生决策碰到偏好原子的次数 |
| 介入 | 建议相位、原生相位、实际覆盖次数 |
| 放弃 | 已赋值、特殊接口接管、原子已使用、冲突额度耗尽 |
| 结果 | 最终模型是否实现建议、实际新观察、实际新增覆盖 |
| 成本 | 摘要准备、分数更新、表安装、热路径查表、日志 |

至少区分：

```text
提出了偏好；
偏好可映射；
原生搜索遇到了这个原子；
偏好与原生相位不同；
实际覆盖了相位；
最终模型满足这个方向。
```

这六件事不能合并成一个“触发次数”。

正式性能运行只保留轻量计数和受限事件记录，不能每次决策都写完整 AST、刷新文件。

对最终满足某个可靠摘要的模型，审计其实际观察包含摘要，并核对实际 covered 增益不小于对应 \(L\)。不满足偏好的模型不要求该下界成立。

不要把同一次最终模型的全部收益，重复归给每一个介入原子；这是共同结果，不是独立因果贡献。

## 七、三个对照配置

新增统一入口，例如：

```text
soft_phase_sampler
```

支持：

| 模式 | 行为 |
|---|---|
| `plain` | 钩子关闭，原式持久求解 |
| `random_soft` | 在同类可介入原子上提供随机相位 |
| `coverage_soft` | 根据实时缺口和条件摘要提供相位 |

### 公平性要求

`random_soft` 与 `coverage_soft` 使用相同的可支持原子目录、映射规则、查询生命周期、介入上限和冲突额度。

`random_soft` 不根据覆盖分数选择真假方向。它用于检验改善是不是仅来自扰动搜索顺序。

二者搜索路径不同，实际遇到的机会和覆盖次数可能不同。记录这些差异，不声称实际介入次数天然相同，也不根据实验结果事后人为配平。

偏好随机数流独立于 Z3 原生随机数流。`plain` 不能因为新增诊断而额外消耗原生随机数。

两个 soft 模式中共同的目录与摘要准备成本应一致核算；plain 不需要的分析不能强迫它执行，以人为拖慢基线。

### 同一模型生成流程

```text
获取或更新偏好表
→ 安装本次查询的只读偏好
→ 对原式执行一次正常 check
→ 清理本次显式偏好
→ 验证完整原模型
→ 计算原 AST 观察
→ 及时输出
→ 完整赋值阻塞
→ 更新覆盖状态
```

不存在“普通查询＋额外覆盖查询”的双重流程。

本轮不启用编译表示及其回退，不启用投影，不要求切换宏观分支。

## 八、本轮暂不改变正式输出筛选规则

为了隔离生成能力，主实验继续输出全部及时、不同、合法模型，包括没有即时覆盖增益的模型。

另外维护一个**只读的观察压缩统计**：

$$
O(m)\setminus O(S)\ne\varnothing
$$

时，把模型记入“带来新观察”的派生序列。

这项统计对三个配置使用同一规则，可以离线从原始轨迹提取，不改变求解器状态、阻塞顺序、偏好更新或正式输出。

不得把“零覆盖增益”直接当作“没有新观察”。第一次出现的0或1可能对后续覆盖有价值。

结果分别报告：

```text
原始不同合法模型前缀覆盖；
新观察派生序列的覆盖与实际到达时间；
真实墙钟覆盖。
```

**不能用过滤后的前缀改善，冒充软偏好生成机制已经改善。**

## 九、先验证语义与接口，再测试性能

### 9.1 软性与生命周期回归

必须验证：

1. 安装、替换、清除偏好前后，用户断言仍然只是原公式与正常完整模型阻塞。
2. 偏好与可满足解冲突时，求解器仍能返回不满足偏好的合法模型。
3. 偏好不覆盖传播，不产生新的 assumptions 或优化目标。
4. 同一持久求解器的第二次及后续查询确实能读取新偏好。
5. 上一次查询的偏好不会无界累积。
6. 回溯和内部重启不会重新发放本次介入额度。
7. 同一原子只介入一次后，可以由原生搜索尝试相反方向。
8. Unknown、超时、取消和异常后，显式偏好状态被正确处理。

### 9.2 钩子关闭与补丁影响

在固定操作额度、没有墙钟边界干扰的小测试中，比较：

```text
原冻结库；
新补丁库且钩子关闭。
```

检查 SAT／UNSAT、完整模型集合、原生决策记录和随机数使用是否一致。若存在差异，先查清补丁副作用。

真实墙钟测试可能因编译布局等产生波动，不能强求两次限时运行完全同序列；但关闭开关后不得留下主动行为变化。

### 9.3 摘要正确性回归

使用可完整枚举的小公式核验：

$$
F\land l\Rightarrow G(l)\subseteq O(m).
$$

覆盖成组常量选择、可区分与不可区分坐标、等式协同、负大整数、一般 OR、嵌套条件、短路访问和共享节点。

增加两个特别重要的反例：

**变量值可确定但节点没有被访问。** 不得计入保证观察。

**单个原子不能推出整个备选。** 不得把该备选所有赋值错误放入摘要。

小型有限枚举应比较三个模式的全部原始模型集合，确保偏好没有遗漏合法模型或错误地产生 UNSAT。

### 9.4 真实公式上的生效检查

在两个 bofill 实例上，记录：

```text
目录是否非空；
多少原子真正映射到内部 literal；
原生搜索是否遇到这些原子；
有没有实际相位覆盖；
覆盖是否只发生在正常决策点；
有没有相位被回溯放弃；
最终模型是否全部满足原公式。
```

如果实际覆盖次数一直为零，首先判为“没有有效测试到机制”，不能直接进入长性能实验或宣称软偏好无效。

不能通过增加硬约束来解决“偏好没有被遇到”的问题。

## 十、小规模实验协议

### 10.1 固定对象

使用当前两个 bofill 实例：

```text
SMT_random_LIA_ex14600_2600_100.smt2
SMT_real_LIA_ex8500_2400_100.smt2
```

它们已经是定向研究对象，不再声称属于未接触评测集。

本轮不重跑 HighDiv。历史 HighDiv 仅作为背景，不能并入本轮同条件对照。

### 10.2 功能曝光测试

完成回归后，先执行：

```text
2个实例 × 1个固定种子 × 3种模式
= 6次30秒会话
```

这一阶段检查真实映射、相位介入、预算与日志，不根据覆盖结果调整参数。

若功能正确、偏好实际生效，则进入正式筛选；不要要求这六次运行先“两个实例全部获胜”才允许检验。

若没有实际介入，应修复映射或说明当前实现不适用，而不是继续延长同样的空运行。

### 10.3 正式筛选

运行：

```text
2个实例
× seed 0、1、2
× plain、random_soft、coverage_soft
= 18次60秒会话
```

不再使用10秒作为主要结论预算，避免首次求解占据大部分时间。但60秒仍是开发筛选，不是长期性能证明。

三个配置从原始输入开始，包含：

```text
解析；
求解器初始化；
首次求解；
摘要准备；
后续查询；
反馈更新；
模型验证；
输出和阻塞。
```

初始模型不使用历史样本，不提供已知解作为提示。

固定三个单核任务槽，每批运行同一实例、同一种子的完整三模式组；组内同步启动，组间屏障，轮换模式与核心对应关系。不要中途改变并发数量。独立审计在采样完成后执行。

### 10.4 主指标

同时报告：

| 指标 | 回答的问题 |
|---|---|
| 不同合法原始模型／秒 | 是否损害候选供给 |
| 新观察数／秒 | 是否产生新的信息 |
| covered bit 随时间增长 | 是否提高最终目标 |
| 前2/5/10/50/100个原始样本覆盖 | 样本是否更互补 |
| 达到相同覆盖的时间 | 是否更快 |
| 首模型时间 | 是否意外损害原有可行性能力 |
| 零新观察候选比例与高原长度 | 是否减少真正的观察重复 |
| 偏好映射、实际覆盖与最终满足情况 | 机制是否确实发挥作用 |
| 全部新增成本 | 收益是否值得开销 |

没有达到指定样本数时保留未完成。零输出、超时、Unknown及失败会话不得删除。

60秒结束时仍在高原的区间标为截止未结束，不能当作自行恢复。

## 十一、怎样决定继续还是停止

本轮必须分开作出三个判断。

### A. 实现是否正确且实际生效

所有原模型合法、摘要条件正确、偏好没有变成约束，并且真实公式上出现了实际原生相位覆盖。

只调用过接口、最终模型偶然满足了某个建议，都不够证明偏好生效。

### B. 覆盖反馈是否比随机扰动有用

分别比较：

```text
coverage_soft − plain
coverage_soft − random_soft
random_soft − plain
```

如果只有随机和覆盖两种偏好都同样改善，暂时只能支持“扰动搜索有效”，不能宣称条件覆盖摘要提供了优势。

如果 coverage 模式提高了模型产量，却没有提高新观察或覆盖，也不算达到本轮目标。

### C. 性能是否值得继续

实验前冻结判断规则，不要求两个实例每个 seed 都必须获胜，也不因一个漂亮正例直接晋级。

至少检查：

```text
是否有重复出现的真实累计覆盖正差；
是否优于同额度随机偏好；
原始候选供给是否出现明显系统性下降；
是否存在早期覆盖的反复退步；
收益是否集中在一个偶然会话；
反馈与钩子开销是否可控。
```

可以将每个实例原始候选吞吐中位数不低于 plain 的90%作为首版保护阈值，但必须同时报告绝对值和每个 seed；这只是实验门槛，不是理论吞吐保证。

若只在一个公式有稳定收益，可以报告“存在有限正面信号，需独立实例验证”，不要立即把整个方向判死，也不要直接扩大到900秒。

若偏好真正生效，但比 plain 和随机偏好都更差，则保留负结果，停止继续增加相位干预强度、摘要大小或新调度机制。

本轮不自动执行900秒实验。

---

**这次最重要的实现边界是：只干预“先试哪一边”，不干预“哪些解才允许返回”。**

这样才能真正检验这条主线，而不是又把软偏好悄悄实现成一个新的硬目标求解器。它仍可能失败，但一旦得到正面结果，就能够更清楚地说明：收益来自覆盖反馈对原生搜索顺序的影响，而不是额外预算、输出筛选或更换求解表示。

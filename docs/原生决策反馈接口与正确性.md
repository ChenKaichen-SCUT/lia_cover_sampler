# 原生决策机会、接口与正确性

基点为 `6b54afe`，新分支 `native-feedback-phase`。旧 `z3_soft_phase.patch`、旧程序、历史结果及 No-Go 保持原样。新补丁在旧补丁之上应用，独立安装于 `dependencies/z3-native-feedback-phase`；四配置均链接这一新库。

## 原生接口

`context::decide()` 已确定变量与原生相位后、写入正常决策文字之前调用新接口。接口收到借用的原子表达式、原生真假、本次查询决策序号和本次查询冲突增量，返回跳过、KeepNative、FlipOnce 或停止。仅 FlipOnce 取反当前相位；不改决策变量、断言、传播、冲突分析或重启算法。

`Z3_solver_set_native_phase_callback` 安装回调并清除旧软偏好表；新程序不同时使用两个接口。计数器属于普通 context 状态，不入 trail：Keep 与 Flip 均耗尽唯一选择点，重启和回溯不能恢复额度。超过前32次原生决策后不再调用回调。已赋值变量及 user propagator 接管的决策安全跳过。关闭回调没有随机数消耗；策略使用独立 RNG。

回调同步执行于 `check()` 内，不返回模型或执行新查询。被缓存表达式使用 `z3::expr` 持有强引用；最多4096项，满后停止后续干预，直到会话结束才销毁。回调只读 AST、进行有界精确线性分类和16维预测，不调用 `simplify()`、文件、Python 或求解器。目录规范化、模型训练及日志写入在查询之间进行。

支持范围不限于原 AST 或旧目录：只要当前已有原子是已识别原整数变量组成的线性关系，即可支持。新产生的等式或比较不能伪造原 AST 身份。未知辅助变量、非线性结构、资源上限和异常均保留原生选择。保存原子表达式及其会话内身份，离线以公式哈希、表达式和原 AST 映射生成稳定身份；数字 AST ID 不进入预测特征。

## 反馈与正式状态

`native_feedback_sampler` 保留原式持久 `simple` 求解器。首个及时合法模型之前不建策略。每个及时、不同、合法原模型均按原顺序正式写出；只有完整模型写完且截止检查通过，才更新 seen0/seen1 和正式去重集合。新增断言仅有完整原变量赋值的精确阻塞。没有候选过滤、重排、目标约束或额外求解机会。

每次查询只生成一个动作反馈，标签对应实际执行的 Keep/Flip。模型最终未实现希望的方向也不修改标签。只有正式输出带来回报；Unknown、重复、迟到及没有输出的回报为0。未选动作的真实回报和成本保持 null，不能把预测补成真实标签。

完整成本使用相邻查询准备边界。上一条区间结束后才能训练其实际动作，维护开销进入当前区间；末次维护为单列尾部。区间之和加尾部必须等于保存的 elapsed，进程墙钟另列。check 已包含钩子，不与嵌套钩子耗时再次相加。5%累计机制保护触发后停止新干预，继续普通查询；必要记录成本照计。

## 回归与独立审计

`native_phase_hook_test` 仅链接 Z3：固定操作额度下比较关闭、始终 Keep、跳过的完整轨迹；枚举全部16个原模型，Flip 后解集合必须一致。另测传播、特殊接口、冲突/回溯/重启、局部超时与外部取消，确认每次最多一个选择和一次相位修改。

`native_feedback_test` 增加新线性关系识别、未知辅助与非线性跳过、强引用生命周期、4096缓存停止、首模型和机制成本保护；测试实际动作单独训练、每动作8条暖启动、固定概率、256窗口、会话隔离及非有限数值。

Python 回归验证完整输出、短路观察、负数及超过64位原整数、有限枚举、截止、无机会不造反馈。合成保存日志分别覆盖 Unknown、重复、迟到、Flip最终未实现，且故意篡改动作标签必须被拒绝。这些是审计回归夹具，不是性能数据。另以固定280次小公式查询重放冷启动、利用及窗口淘汰。

独立审计先调用冻结 `ManualSatisfiesMetric` 逐模型验证原式、seen0/seen1 指纹、观察增量与覆盖累计。然后用独立 Python 线性解析重算原子依赖、系数特征、旧目录标签及有界原AST父节点集合；依查询时间重放正式状态、决策前上下文和动作概率。岭回归从保存窗口重新构造矩阵，不使用 C++ 增删外积代码。审计中禁用 solver/optimizer/fixedpoint 搜索入口，只解析和求值。预测误差仅对实际选择动作计算。

## 可复现命令

```bash
python3 scripts/make_native_feedback_patch.py
python3 scripts/build_native_feedback_dependency.py --jobs 12
python3 scripts/build_native_feedback_dependency.py --sanitize --jobs 8
cmake -S . -B build/native_feedback/release -DCMAKE_BUILD_TYPE=Release -DLIA_ENABLE_SOFT_PHASE=ON -DLIA_ENABLE_NATIVE_FEEDBACK=ON -DZ3_PREFIX="$PWD/dependencies/z3-native-feedback-phase/install"
cmake --build build/native_feedback/release -j15
cmake -S . -B build/native_feedback/sanitize -DCMAKE_BUILD_TYPE=Debug -DLIA_ENABLE_SOFT_PHASE=ON -DLIA_ENABLE_NATIVE_FEEDBACK=ON -DZ3_PREFIX="$PWD/dependencies/z3-native-feedback-phase/install-sanitize" '-DCMAKE_CXX_FLAGS=-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie' '-DCMAKE_EXE_LINKER_FLAGS=-fsanitize=address,undefined -no-pie'
cmake --build build/native_feedback/sanitize -j7
python3 scripts/test_native_feedback_build.py --build build/native_feedback/release --out results/native_feedback_validation/release
python3 scripts/test_native_feedback_build.py --build build/native_feedback/sanitize --out results/native_feedback_validation/sanitize --sanitize
python3 scripts/finalize_native_feedback_build.py
```

构建脚本拒绝覆盖已经安装的新库；重放须从新的构建目录开始。可使用历史对象的独立副本加速依赖构建，不使用硬链接，修改头文件的依赖全部重新编译。两套历史库与冻结原库的哈希在交付清单中复核。构建失败和修正记录保留在本轮验证目录；性能运行必须以最终完整回归通过为门槛。
